[quality] high
T: Publikuj wartościowe treści
D: Treść ma odpowiadać na realną potrzebę czytelnika: być oryginalna, kompletna i oparta na doświadczeniu oraz wiedzy autora (E-E-A-T), a nie pisana pod słowa kluczowe. Żadna optymalizacja techniczna tego nie zastąpi.
W: W marcu 2024 r. Google włączył ocenę przydatności treści do głównych systemów rankingowych; słabe treści mogą obniżać widoczność całego serwisu, nie tylko pojedynczej strony.
W: Informacje z pierwszej ręki (własne zdjęcia, sprawdzone ceny, relacja z pobytu w hotelu) to coś, czego nie skopiuje konkurencja ani nie wygeneruje model AI z ogólnodostępnych danych.
W: Czytelnik, który znalazł odpowiedź, zostaje dłużej, wraca i częściej rezerwuje; tekst "dla robota" kończy się powrotem do wyników wyszukiwania.
V: Oceń tekst pytaniami z poradnika Google o przydatnych treściach (np. "czy po lekturze czytelnik wie wystarczająco dużo, by osiągnąć cel?") i porównaj z pierwszą stroną wyników: co wnosisz ponad nie.
```html Treść z doświadczeniem z pierwszej ręki
<article>
  <h1>Hotel Kalimera Beach na Krecie: recenzja po tygodniu z dziećmi</h1>
  <p>Byliśmy tu w czerwcu 2026 z dwójką dzieci (4 i 7 lat); pobyt opłaciliśmy sami.</p>
  <figure>
    <!-- Own photo, not a stock or hotel marketing image -->
    <img src="/img/kalimera-pokoj-rodzinny.webp" width="1200" height="800"
         alt="Pokój rodzinny z widokiem na basen, łóżeczko dziecięce przy oknie">
    <figcaption>Pokój rodzinny nr 214; łóżeczko dostawiono bez dopłaty.</figcaption>
  </figure>
  <h2>Co nas zaskoczyło</h2>
  <ul>
    <li>Zejście do morza jest kamieniste: zabierz buty do wody.</li>
    <li>Transfer z lotniska w Heraklionie trwał 35 minut, a nie 20 jak w katalogu.</li>
  </ul>
</article>
```
X: Parafrazowanie artykułów z czołówki wyników bez dodania żadnej nowej informacji.
X: Mierzenie jakości liczbą słów lub gęstością fraz zamiast tego, czy tekst odpowiada na pytanie użytkownika.

[ymyl-detection] high
T: Rozpoznaj treści YMYL
D: "Your Money or Your Life" to tematy, które mogą wpłynąć na zdrowie, finanse, bezpieczeństwo lub prawa człowieka (np. ubezpieczenia podróżne, szczepienia przed wyjazdem, płatności, prawa pasażera). Wymagają wyższych standardów: autora z kwalifikacjami, recenzji eksperta, źródeł i daty weryfikacji.
W: Wytyczne dla oceniających jakość (Search Quality Rater Guidelines) wymagają przy YMYL najwyższego poziomu zaufania; ta sama treść bez autora i źródeł zostanie oceniona niżej niż przy zwykłym temacie.
W: Błąd ma realne skutki: nieaktualna informacja o wizie lub zakresie polisy może kosztować klienta odmowę wjazdu albo tysiące złotych za leczenie za granicą.
W: Oznaczenie kategorii YMYL w CMS pozwala wymusić proces (recenzja, źródła, data weryfikacji) zamiast liczyć na pamięć redaktora.
V: Przejrzyj kategorie treści i oznacz YMYL; na tych stronach sprawdź podpis autora, recenzenta, datę weryfikacji i przypisy do źródeł pierwotnych.
```ts Walidacja w CMS przed publikacją
// cms/validators/ymyl.ts
const YMYL_CATEGORIES = new Set(['ubezpieczenia', 'zdrowie-w-podrozy', 'wizy', 'platnosci', 'prawa-pasazera']);

export function validateYmyl(post: Post): string[] {
  if (!YMYL_CATEGORIES.has(post.category)) return [];
  const errors: string[] = [];
  if (!post.author?.bio) errors.push('YMYL: author with bio is required');
  if (!post.reviewedBy) errors.push('YMYL: expert reviewer is required');
  if (!post.reviewedAt) errors.push('YMYL: review date is required');
  if (post.sources.length < 2) errors.push('YMYL: cite at least two primary sources');
  return errors;
}
```
X: Traktowanie poradnika "jak odzyskać pieniądze za odwołany lot" jak zwykłego wpisu blogowego, bez weryfikacji przez prawnika.
X: Jednorazowa weryfikacja bez terminu kolejnego przeglądu; przepisy i warunki polis zmieniają się co sezon.

[about-page] medium
T: Strona "O nas"
D: Strona z konkretami: kim jesteście, od kiedy działacie, kto stoi za firmą, dane rejestrowe i osiągnięcia. Podlinkowana z każdej strony, zwykle w stopce.
W: Wytyczne dla oceniających jakość każą sprawdzać, kto odpowiada za witrynę; brak takiej informacji to sygnał niskiego zaufania, szczególnie przy sprzedaży wycieczek.
W: Klient przed pierwszą rezerwacją u mniej znanego biura szuka dowodów, że firma istnieje naprawdę: zdjęć zespołu, roku założenia, numeru w rejestrze.

[affiliate-disclosure] medium
T: Oznaczaj linki afiliacyjne i treści sponsorowane
D: Użytkownik musi wiedzieć o powiązaniach finansowych: widoczna informacja przy treści, a linki płatne i afiliacyjne oznaczone `rel="sponsored"`. To wymóg zaufania, zasad Google i prawa.
W: Google wymaga oznaczania linków płatnych; kupione lub sprzedane linki bez `sponsored` (albo `nofollow`) mogą zostać uznane za spam linkowy.
W: Ukryta reklama jest w Polsce nieuczciwą praktyką rynkową (ustawa o przeciwdziałaniu nieuczciwym praktykom rynkowym); UOKiK wydał też rekomendacje oznaczania treści reklamowych.
W: Jawność buduje zaufanie: czytelnik, który sam odkryje ukrytą prowizję, przestaje wierzyć całemu serwisowi.
V: Przejrzyj artykuły z linkami partnerskimi: czy informacja jest widoczna przed pierwszym linkiem i czy każdy taki link ma `rel="sponsored"` (DevTools lub crawler z ekstrakcją atrybutu `rel`).
```html
<p class="disclosure" role="note">
  Artykuł zawiera linki partnerskie. Jeśli zarezerwujesz przez nie hotel,
  otrzymamy prowizję; cena dla Ciebie się nie zmienia.
  <a href="/jak-zarabiamy">Jak zarabiamy</a>
</p>

<!-- Paid or affiliate link: "sponsored" is preferred, "nofollow" is still accepted -->
<a href="https://partner.example.com/hotel/123?aff=exm" rel="sponsored noopener" target="_blank">
  Sprawdź ceny w Hotel Kalimera Beach
</a>
```
X: Informacja o współpracy tylko w stopce lub regulaminie, daleko od linków.
X: Dodawanie `rel="sponsored"` do zwykłych linków wewnętrznych serwisu.
S: Google: Qualify your outbound links | https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links

[ai-content] medium
T: Weryfikuj treści generowane przez AI
D: AI może pomagać w researchu i pisaniu, ale masowe generowanie stron bez wartości dodanej Google traktuje jako spam ("scaled content abuse"). Każdy tekst przechodzi redakcję człowieka: fakty, źródła, własna perspektywa.
W: Modele językowe przewidują prawdopodobne słowa, a nie sprawdzają faktów; zmyślona godzina odprawy czy wymóg wizowy trafia prosto do klienta.
W: Polityka "scaled content abuse" (od marca 2024 r.) dotyczy masowej produkcji stron niezależnie od tego, czy pisze je człowiek, czy AI; karane jest zachowanie, nie narzędzie.
W: Google zaleca sprawdzać także generowane automatycznie tytuły, meta description, dane strukturalne i teksty alternatywne obrazów.
V: Redakcyjny przegląd przed publikacją: weryfikacja faktów, źródła, unikalne informacje, ton marki; w CMS zapisz, kto i kiedy zatwierdził tekst.
```ts Bramka publikacji w CMS
// AI-assisted drafts cannot be published without a human fact-check
type Draft = {
  aiAssisted: boolean;
  factCheckedBy?: string; // editor id
  factCheckedAt?: string; // ISO 8601
  sources: string[];
};

export function canPublish(d: Draft): { ok: boolean; reason?: string } {
  if (!d.aiAssisted) return { ok: true };
  if (!d.factCheckedBy || !d.factCheckedAt) return { ok: false, reason: 'Missing human fact-check' };
  if (d.sources.length === 0) return { ok: false, reason: 'AI-assisted text needs sources' };
  return { ok: true };
}
```
X: Generowanie setek stron "Wakacje w {miasto}" z jednego promptu.
X: Obrazy produktów z AI bez metadanych IPTC `DigitalSourceType`, których Google Merchant Center wymaga dla treści generowanych.
S: Google: Guidance about AI-generated content | https://developers.google.com/search/blog/2023/02/google-search-and-ai-content ; Google: Using generative AI content on your website | https://developers.google.com/search/docs/fundamentals/using-gen-ai-content

[anchor-text] medium
T: Opisowy tekst kotwic linków
D: Tekst linku mówi, czego dotyczy strona docelowa ("oferty last minute do Grecji"), a nie "kliknij tutaj". Pomaga to wyszukiwarkom i użytkownikom, także czytników ekranu.
W: Google wykorzystuje tekst kotwic do zrozumienia strony docelowej; to nawet jedno ze źródeł, z których powstaje tytuł w wynikach.
W: Użytkownicy czytników ekranu często przeglądają samą listę linków; dziesięć razy "więcej" nic im nie mówi (WCAG 2.4.4 Link Purpose).
W: Opisowe kotwice ułatwiają skanowanie tekstu wzrokiem: czytelnik wie, dokąd prowadzi link, zanim kliknie.
V: Crawler (np. Screaming Frog) z raportem tekstów kotwic: szukaj "kliknij tutaj", "więcej", "link" oraz pustych kotwic (np. same ikony).
```html Źle
<p>Szukasz tanich wakacji? <a href="/grecja/last-minute">Kliknij tutaj</a>.</p>
<!-- Icon-only link: empty accessible name and no anchor text -->
<a href="/kreta"><svg aria-hidden="true"><use href="#icon-arrow"/></svg></a>
```
```html Dobrze
<p>Zobacz <a href="/grecja/last-minute">oferty last minute do Grecji</a> z wylotem w tym tygodniu.</p>
<a href="/kreta">
  <svg aria-hidden="true"><use href="#icon-arrow"/></svg>
  <span class="visually-hidden">Wakacje na Krecie</span>
</a>
```
X: Upychanie dokładnej frazy w każdej kotwicy ("tanie wakacje Grecja tanie") wygląda na manipulację.

[article-links] medium
T: Zrównoważone linkowanie w artykułach
D: Artykuł linkuje do powiązanych treści w serwisie i do autorytatywnych źródeł zewnętrznych; orientacyjnie 2-3 linki wewnętrzne i 1-2 zewnętrzne, proporcjonalnie do długości tekstu i tylko tam, gdzie pomagają czytelnikowi.
W: Linki wewnętrzne pozwalają Google odkryć i zrozumieć powiązane strony; strona bez linków przychodzących ("osierocona") może w ogóle nie trafić do indeksu.
W: Link do źródła zewnętrznego (np. serwisu gov.pl o paszportach) pozwala czytelnikowi sprawdzić informację i pokazuje, że autor jej nie wymyślił.
W: Przesyt linków rozprasza i wygląda jak farma linków; czytelnik nie wie, który jest naprawdę ważny.
V: Policz linki w kilku reprezentatywnych artykułach (np. skryptem poniżej w konsoli DevTools) i znajdź w crawlerze strony bez linków wewnętrznych.
```js Konsola DevTools: linki w treści artykułu
const article = document.querySelector('article');
const links = [...article.querySelectorAll('a[href]')];
const internal = links.filter((a) => a.hostname === location.hostname);
const external = links.filter((a) => a.hostname !== location.hostname);
const words = article.innerText.split(/\s+/).length;
console.table({ words, internal: internal.length, external: external.length });
console.log(external.map((a) => `${a.href} rel=${a.rel || '-'}`));
```
X: Linkowanie wyłącznie do strony głównej lub kategorii zamiast do konkretnych, powiązanych artykułów.

[author-byline] medium
T: Widoczny autor treści
D: Imię i nazwisko autora widoczne przy treści, z linkiem do jego profilu w serwisie, oraz zgodny z tym `author` w danych strukturalnych.
W: Czytelnik i oceniający jakość muszą wiedzieć, kto odpowiada za tekst; anonimowy poradnik o ubezpieczeniu podróżnym budzi mniejsze zaufanie.
W: Google używa `author.url` lub `sameAs`, by odróżniać autorów o tym samym nazwisku i łączyć ich teksty.
W: Profil autora z listą artykułów to dodatkowa wartościowa strona i ścieżka linkowania wewnętrznego.

[citations] medium
T: Cytuj wiarygodne źródła
D: Linki do źródeł pierwotnych (urzędy, przepisy, badania, oficjalna dokumentacja) przy konkretnych twierdzeniach uwiarygadniają treść i pozwalają czytelnikowi ją sprawdzić.
W: Wytyczne dla oceniających jakość traktują poparcie twierdzeń źródłami jako sygnał wiarygodności, zwłaszcza w tematach YMYL.
W: Źródło pierwotne (np. rozporządzenie UE 261/2004 o prawach pasażerów) jest stabilniejsze niż cudzy wpis na blogu i łatwiej sprawdzić, czy przepis się zmienił.
W: Przypisy ułatwiają redakcji okresową weryfikację: wiadomo, co sprawdzić, gdy zmienią się przepisy lub ceny.
V: Przejrzyj kluczowe artykuły: czy każda liczba, przepis i obietnica ma link do źródła i czy linki działają (crawler: linki zewnętrzne z kodem 4xx/5xx).

[contact-page] medium
T: Pełna strona kontaktowa
D: Kilka form kontaktu (formularz, telefon, e-mail, adres, godziny pracy infolinii) na jednej łatwo dostępnej stronie. To sygnał zaufania i wymóg przepisów dla sprzedaży online.

W: Klient z problemem na wyjeździe szuka telefonu alarmowego; jego brak kończy się złą opinią w sieci i reklamacją.
W: Wytyczne dla oceniających jakość wskazują brak informacji kontaktowych w serwisie sprzedażowym jako sygnał niskiej jakości.

[content-dates] medium

D: Widoczna data publikacji i ostatniej aktualizacji, oznaczona elementem `<time datetime>`, oraz te same daty w `datePublished` i `dateModified` w danych strukturalnych (ISO 8601 ze strefą czasową).

```ts dateModified tylko przy istotnej zmianie
type Revision = { body: string; substantive: boolean }; // editor ticks "substantive change"

const normalize = (s: string) => s.replace(/\s+/g, ' ').trim();

export function nextDateModified(prevDate: string, prevBody: string, rev: Revision): string {
  const changed = normalize(prevBody) !== normalize(rev.body);
  return changed && rev.substantive ? new Date().toISOString() : prevDate;
}
```

[meta-in-body] high
T: Meta tagi tylko w head
D: `<title>`, `<meta>` i `<link rel="canonical">` muszą znaleźć się w `<head>`; w `<body>` wyszukiwarki je ignorują. Head bywa zamykany za wcześnie przez niedozwolony element (np. `<img>`, `<iframe>`, `<div>`) albo tagi trafiają do body przez skrypt.
W: Parser HTML na pierwszym niedozwolonym elemencie niejawnie zamyka `<head>`; wszystko dalej, łącznie z canonical i robots, ląduje w `<body>`.
W: Google wprost zapowiada, że po nieprawidłowym elemencie w head ignoruje wszystkie kolejne elementy head (dozwolone są tylko `title`, `meta`, `link`, `script`, `style`, `base`, `noscript`, `template`).
W: Błąd jest niewidoczny dla użytkownika i często pojawia się po dodaniu piksela marketingowego przez menedżer tagów.
V: Porównaj źródło strony z wyrenderowanym DOM (DevTools, panel Elements): czy canonical, robots i hreflang są w head; walidator HTML (validator.w3.org) wskaże niedozwolone elementy.
```html Źle
<head>
  <title>Wakacje w Grecji | Example Travel</title>
  <img src="https://tracker.example.com/px.gif" alt=""> <!-- implicitly closes <head> -->
  <link rel="canonical" href="https://example.pl/wakacje/grecja"> <!-- now in <body>, ignored -->
</head>
```
```html Dobrze
<head>
  <title>Wakacje w Grecji | Example Travel</title>
  <link rel="canonical" href="https://example.pl/wakacje/grecja">
</head>
<body>
  <noscript><img src="https://tracker.example.com/px.gif" alt=""></noscript>
```
X: Wstawianie meta tagów skryptem do `body`; w Next.js używaj Metadata API, a w React 19 `<title>` i `<meta>` renderowane w komponencie są automatycznie przenoszone do head.

T: Poprawna struktura HTML
D: Niezamknięte lub źle zagnieżdżone tagi mogą sprawić, że przeglądarka i Googlebot zinterpretują stronę inaczej, niż zamierzałeś, np. element niedozwolony w `<head>` zamyka go przedwcześnie i dalsze meta tagi lądują w `<body>`.

```html Źle
</head>
```

[canonical-chain] medium
T: Canonical wskazuje bezpośrednio adres docelowy
D: Canonical prowadzi wprost do adresu, który zwraca 200, jest indeksowalny i ma canonical na siebie. Canonical do przekierowania, błędu lub strony z innym canonicalem to sprzeczny sygnał.
W: Canonical to dla Google tylko wskazówka; gdy cel przekierowuje albo wskazuje dalej, Google często ją ignoruje i sam wybiera adres kanoniczny.


[indexability-conflicts] medium
T: Spójne sygnały indeksowania
D: robots.txt, meta robots, `X-Robots-Tag`, canonical i sitemap nie mogą sobie przeczyć (np. canonical do strony z noindex albo adres z sitemap zablokowany w robots.txt).
W: Przy sprzecznych sygnałach Google rozstrzyga sam i wynik bywa nieprzewidywalny: indeksuje inny adres niż wskazany w canonical albo pomija stronę.
W: Typowe konflikty: canonical do strony noindex, adres z sitemap zablokowany w robots.txt, noindex razem z canonicalem na inny adres, `index` w meta i `noindex` w nagłówku.
W: Sygnały pochodzą z różnych warstw (CDN, serwer, framework, CMS), więc konflikt zwykle nie jest widoczny w żadnym pojedynczym pliku.
V: Crawler z raportem indeksowalności; Inspekcja adresu URL pokazuje canonical deklarowany i wybrany przez Google.
```ts Wykrywanie konfliktów w audycie
type PageSignals = {
  url: string; status: number; inSitemap: boolean;
  robotsTxtAllowed: boolean; noindex: boolean; canonical: string | null;
};

export function findConflicts(p: PageSignals): string[] {
  const issues: string[] = [];
  if (p.inSitemap && p.noindex) issues.push("noindex page listed in sitemap");
  if (p.inSitemap && !p.robotsTxtAllowed) issues.push("sitemap URL blocked by robots.txt");
  if (p.noindex && !p.robotsTxtAllowed) issues.push("noindex invisible: blocked by robots.txt");
  if (p.noindex && p.canonical && p.canonical !== p.url) issues.push("noindex plus canonical to another URL");
  if (p.canonical === p.url && p.status !== 200) issues.push("self-canonical on non-200 page");
  return issues;
}
```
X: Ustawianie noindex i canonicala na inny adres jednocześnie "na wszelki wypadek".

[indexability] medium
T: Ważne strony są indeksowalne

[parameters] medium
T: Ogranicz zbędne parametry URL
D: Parametry sortowania, filtrów i śledzenia tworzą tysiące wariantów adresów. Używaj canonical, nie linkuj wewnętrznie do adresów z UTM i ogranicz kombinacje filtrów dostępne dla robotów.
W: Kilka filtrów z kilkoma wartościami i kilka sortowań to tysiące kombinacji; robot marnuje na nie budżet zamiast odwiedzać nowe oferty.

```ts Canonical tylko z dozwolonymi parametrami
const INDEXABLE_PARAMS = new Set(["page"]); // filters, sort and utm are dropped

export function canonicalFor(rawUrl: string): string {
  const url = new URL(rawUrl);
  for (const key of [...url.searchParams.keys()]) {
    if (!INDEXABLE_PARAMS.has(key)) url.searchParams.delete(key);
  }
  url.searchParams.sort(); // stable order: ?a=1&b=2 equals ?b=2&a=1
  url.hash = "";
  return url.toString();
}

canonicalFor("https://example.pl/wakacje/grecja?sort=cena&utm_source=fb&page=2");
// "https://example.pl/wakacje/grecja?page=2"
```

X: Identyfikator sesji lub koszyka w parametrze adresu.

T: Bez niepoprawnych linków
D: Puste `href`, `href="#"` bez funkcji, literówki w schemacie (`htp://`), `javascript:` jako nawigacja. Roboty i czytniki ekranu potrzebują prawdziwych adresów w `<a href>`.

```ts app/oferty/sitemap.ts
import type { MetadataRoute } from "next";
import { countIndexableOffers, getIndexableOffers } from "@/lib/offers";

const PER_FILE = 45_000; // below the 50 000 URL limit per file

export async function generateSitemaps() {
  const total = await countIndexableOffers();
  return Array.from({ length: Math.ceil(total / PER_FILE) }, (_, id) => ({ id }));
}

export default async function sitemap({ id }: { id: Promise<string> }): Promise<MetadataRoute.Sitemap> {
  const page = Number(await id);
  const offers = await getIndexableOffers({ offset: page * PER_FILE, limit: PER_FILE });
  return offers.map((o) => ({ url: `https://example.pl/oferty/${o.slug}`, lastModified: o.updatedAt }));
}
```

[special-chars] medium

D: Spacje, wielkie litery, znaki specjalne i polskie znaki diakrytyczne bywają kodowane (`%C4%85`) i źle wyglądają przy udostępnianiu. Transliteruj (ą → a).

```ts lib/slugify.ts
const PL_MAP: Record<string, string> = {
  ą: "a", ć: "c", ę: "e", ł: "l", ń: "n", ó: "o", ś: "s", ź: "z", ż: "z",
};

export function slugify(input: string): string {
  return input
    .toLowerCase()
    .replace(/[ąćęłńóśźż]/g, (ch) => PL_MAP[ch])
    .normalize("NFKD")                 // split other accents (é becomes e + mark)
    .replace(/[̀-ͯ]/g, "")   // drop combining marks
    .replace(/[^a-z0-9]+/g, "-")       // anything else becomes a hyphen
    .replace(/^-+|-+$/g, "");          // trim leading and trailing hyphens
}

```

[stop-words] low

```ts lib/slug-words.ts
// Conjunctions and prepositions usually safe to drop from new slugs.
// Meaning-changing words like "bez" (without) or "z" (with) are kept on purpose.
const STOP_WORDS = new Set(["i", "oraz", "w", "we", "na", "do", "o", "the", "and", "of", "in"]);

export function trimStopWords(slug: string): string {
  const parts = slug.split("-").filter((word) => !STOP_WORDS.has(word));
  return parts.length >= 2 ? parts.join("-") : slug; // never collapse to one word
}
```
