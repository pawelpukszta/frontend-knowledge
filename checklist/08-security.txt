@cl-group HTTPS

[https] critical
T: Wszystkie strony przez HTTPS
D: Każda strona, zasób i endpoint API jest dostępny wyłącznie przez HTTPS z ważnym certyfikatem i nowoczesnym TLS (1.2 lub 1.3). HTTPS szyfruje komunikację, chroni przed podmianą treści i jest warunkiem wielu API przeglądarki.
W: Bez HTTPS każdy w tej samej sieci Wi-Fi (lotnisko, hotel) może podejrzeć lub podmienić treść strony, w tym numer konta do przelewu czy formularz logowania.
W: Service Worker, geolokalizacja, Web Crypto, schowek czy HTTP/2 i HTTP/3 w przeglądarkach działają tylko w bezpiecznym kontekście.
W: Chrome oznacza strony HTTP jako "Niezabezpieczona", co odstrasza klientów przed podaniem danych do rezerwacji; HTTPS jest też sygnałem rankingowym Google.
V: Otwórz kilka podstron i sprawdź kłódkę oraz `window.isSecureContext` w konsoli; SSL Labs dla konfiguracji certyfikatu i protokołów (cel: ocena A lub A+).
```bash Szybka kontrola certyfikatu i protokołu
# Certificate validity dates and issuer
openssl s_client -connect example.pl:443 -servername example.pl </dev/null 2>/dev/null \
  | openssl x509 -noout -issuer -dates

# Old protocols should be rejected (expect a handshake failure)
openssl s_client -connect example.pl:443 -tls1_1 </dev/null

# Final URL and status after redirects
curl -sSIL http://example.pl/ | grep -iE '^(HTTP|location)'
```
X: Ręczne odnawianie certyfikatów zamiast automatu (ACME, Let's Encrypt); wygasły certyfikat blokuje całą stronę.
X: HTTPS tylko na stronach logowania i płatności, a reszta serwisu po HTTP.
S: Qualys: SSL Labs Server Test | https://www.ssllabs.com/ssltest/

[http-to-https] critical
T: Przekierowanie HTTP na HTTPS
D: Każde żądanie `http://` dostaje 301 (lub 308) na odpowiedni adres `https://` z tą samą ścieżką i parametrami, bez łańcuchów przekierowań.
W: Użytkownicy wpisują adres bez protokołu, a stare linki i zakładki prowadzą na `http://`; bez przekierowania trafiają na niezabezpieczoną wersję lub błąd.
W: Przekierowanie stałe przenosi sygnały SEO na wersję HTTPS; 302 lub łańcuch `http` → `www` → `https` rozprasza je i dodaje opóźnienie przy każdej wizycie.
W: Zachowanie ścieżki ma znaczenie: przekierowanie wszystkiego na stronę główną gubi link do konkretnej oferty z maila czy reklamy.
V: `curl -I http://twoja-domena.pl/sciezka?x=1` powinien zwrócić jeden 301 z `Location` na ten sam adres w HTTPS; sprawdź też wariant z `www`.
```http Pojedyncze przekierowanie z zachowaniem ścieżki
GET /wakacje/grecja?termin=lipiec HTTP/1.1
Host: example.pl

HTTP/1.1 301 Moved Permanently
Location: https://example.pl/wakacje/grecja?termin=lipiec
```
```js Express 5 (za proxy lub load balancerem)
app.set('trust proxy', 1); // read X-Forwarded-Proto from the load balancer

app.use((req, res, next) => {
  if (req.secure) return next();
  res.redirect(301, `https://${req.hostname}${req.originalUrl}`);
});
```
X: Przekierowanie wykonywane w JavaScripcie na stronie, czyli dopiero po załadowaniu treści przez HTTP.
X: Łańcuch kilku przekierowań zamiast jednego bezpośrednio na adres docelowy.

[mixed-content] high
T: Bez mixed content
D: Strona HTTPS nie ładuje zasobów przez HTTP. Przeglądarki blokują takie skrypty, style i ramki, a obrazy oraz media automatycznie podnoszą do HTTPS, co psuje je, gdy serwer nie obsługuje HTTPS.
W: Zablokowany skrypt lub arkusz stylów z adresu `http://` potrafi wyłączyć kalendarz rezerwacji czy koszyk bez widocznego komunikatu dla użytkownika.
W: Zasób przez HTTP może zostać podmieniony w sieci, co niweczy ochronę całej strony.
W: Mixed content często wraca razem z treściami z CMS (wklejone obrazy z `http://`) i starymi skryptami partnerów.
V: Konsola przeglądarki (ostrzeżenia Mixed Content), crawler szukający adresów `http://` w źródłach; tymczasowo nagłówek CSP w trybie Report-Only do zbierania naruszeń.
```html Źle
<script src="http://widgets.partner.example/booking.js"></script>
<img src="http://cdn.example.pl/img/hotel.jpg" alt="Hotel nad morzem" width="800" height="533" />
```
```html Dobrze
<script src="https://widgets.partner.example/booking.js" defer></script>
<img src="/img/hotel.jpg" alt="Hotel nad morzem" width="800" height="533" />
<!-- Safety net for legacy CMS content, sent as a response header:
     Content-Security-Policy: upgrade-insecure-requests -->
```
X: Poleganie wyłącznie na `upgrade-insecure-requests` zamiast poprawienia adresów w kodzie i CMS.
S: MDN: Mixed content | https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content

[hsts] high
T: Nagłówek HSTS
D: `Strict-Transport-Security: max-age=63072000; includeSubDomains` wymusza HTTPS w przeglądarce przy kolejnych wizytach. Opcjonalnie `preload` i zgłoszenie na hstspreload.org.
W: Przekierowanie 301 nie chroni pierwszego żądania po `http://`; atakujący w publicznej sieci może je przechwycić (SSL stripping). HSTS sprawia, że przeglądarka od razu łączy się przez HTTPS.
W: Przy HSTS przeglądarka nie pozwala zignorować błędu certyfikatu, więc użytkownik nie "kliknie dalej" na fałszywej stronie.
W: Lista preload chroni nawet pierwszą wizytę, ale wpis jest trudny do wycofania; każda subdomena musi mieć działający HTTPS.
V: Nagłówki odpowiedzi w DevTools lub `curl -sI https://example.pl`; securityheaders.com; w Chrome `chrome://net-internals/#hsts` pokazuje stan domeny.
```http Wdrażanie stopniowe
# Step 1: short max-age, verify all subdomains work over HTTPS
Strict-Transport-Security: max-age=86400; includeSubDomains

# Step 2: two years, ready for the preload list
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```
X: Dodanie `includeSubDomains` i `preload`, gdy jakaś subdomena (np. stary panel partnera) działa tylko po HTTP.
X: Wysyłanie HSTS w odpowiedziach HTTP; przeglądarka uwzględnia go tylko przez HTTPS.
S: MDN: Strict-Transport-Security | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Strict-Transport-Security

[form-https] critical
T: Formularze wysyłane przez HTTPS
D: Akcja każdego formularza (logowanie, płatność, kontakt) i każde żądanie `fetch` z danymi wskazuje adres HTTPS; przeglądarki ostrzegają przy wysyłce przez HTTP.
W: Formularz na stronie HTTPS wysyłany na `http://` przesyła hasło, PESEL czy dane kontaktowe otwartym tekstem.
W: Chrome pokazuje pełnoekranowe ostrzeżenie przed wysłaniem niezabezpieczonego formularza, co praktycznie zabija konwersję.
W: Dyrektywa CSP `form-action` dodatkowo ogranicza, dokąd formularz może zostać wysłany, nawet gdy ktoś wstrzyknie własny `<form>`.
V: Przegląd atrybutów `action` i zapytań w Network (kolumna Scheme); wyszukaj w kodzie `action="http:` i `fetch('http:`.
```html Źle
<form action="http://api.example.pl/newsletter" method="post">
```
```html Dobrze
<!-- Relative URL inherits HTTPS from the page -->
<form action="/api/newsletter" method="post">
  <label for="email">E-mail</label>
  <input id="email" name="email" type="email" autocomplete="email" required />
  <button type="submit">Zapisz się</button>
</form>
<!-- Response header: Content-Security-Policy: form-action 'self' -->
```
X: Poprawny `action`, ale skrypt wysyłający dane do zewnętrznego narzędzia marketingowego przez `http://`.

[content-security-policy] high
T: Content Security Policy
D: CSP ogranicza źródła skryptów, stylów, obrazów i połączeń, więc wstrzyknięty skrypt się nie wykona. Najskuteczniejsza jest strict CSP oparta na nonce i `'strict-dynamic'`; wdrażaj ją, zaczynając od trybu Report-Only.
W: XSS jest jedną z najczęstszych podatności aplikacji webowych; CSP to druga linia obrony, gdy błąd w escapowaniu już się zdarzył.
W: Listy dozwolonych domen (allowlist) łatwo obejść przez hostowane na nich biblioteki i endpointy JSONP; nonce z `'strict-dynamic'` jest odporny na ten problem.
W: Nonce musi być losowy i nowy przy każdym żądaniu; w Next.js oznacza to dynamiczne renderowanie stron, co ma koszt wydajnościowy i wyklucza cache CDN dla HTML.
W: Tryb Report-Only pozwala zebrać naruszenia z produkcji (skrypty marketingowe, rozszerzenia) bez psucia strony.
V: Nagłówek odpowiedzi w DevTools, CSP Evaluator, konsola (naruszenia); po wdrożeniu monitoruj raporty z endpointu `report-to`.
```ts proxy.ts (Next.js 16)
import { NextRequest, NextResponse } from 'next/server';

export function proxy(request: NextRequest) {
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64');
  const csp = [
    "default-src 'self'",
    `script-src 'nonce-${nonce}' 'strict-dynamic'`,
    `style-src 'self' 'nonce-${nonce}'`,
    "img-src 'self' blob: data: https://res.cloudinary.com",
    "object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'",
  ].join('; ');
  const requestHeaders = new Headers(request.headers);
  requestHeaders.set('x-nonce', nonce); // read in Server Components via headers()
  requestHeaders.set('Content-Security-Policy', csp); // Next.js applies the nonce to its scripts
  const response = NextResponse.next({ request: { headers: requestHeaders } });
  response.headers.set('Content-Security-Policy', csp);
  return response;
}
```
```http Najpierw tryb raportowania
# Violations are reported, nothing is blocked yet
Reporting-Endpoints: csp="https://example.pl/api/csp-reports"
Content-Security-Policy-Report-Only: script-src 'nonce-r4nd0m' 'strict-dynamic';
  object-src 'none'; base-uri 'none'; report-to csp
# The nonce is generated per response; switch to the enforcing header once reports are clean
```
X: `'unsafe-inline'` w `script-src` bez nonce; polityka wtedy praktycznie nie chroni przed XSS.
X: Stały nonce zapisany w konfiguracji lub cache'owany razem ze stroną.
S: web.dev: Mitigate XSS with a strict CSP | https://web.dev/articles/strict-csp ; OWASP: Content Security Policy Cheat Sheet | https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html ; Next.js: Content Security Policy | https://nextjs.org/docs/app/guides/content-security-policy

[x-content-type] high
T: X-Content-Type-Options: nosniff
D: Nagłówek `X-Content-Type-Options: nosniff` zabrania przeglądarce zgadywania typu MIME, co chroni przed wykonaniem pliku (np. uploadu) jako skryptu lub HTML. Wymaga poprawnego `Content-Type` dla każdego zasobu.
W: Bez `nosniff` plik tekstowy lub "obrazek" wgrany przez użytkownika, zawierający HTML i JavaScript, może zostać zinterpretowany jako strona i wykonać skrypt (XSS).
W: Z `nosniff` przeglądarka blokuje skrypty i style podane z niewłaściwym typem MIME, więc pomyłka w konfiguracji serwera nie staje się furtką.
W: To jeden nagłówek bez wpływu na wydajność; OWASP zaleca go dla wszystkich odpowiedzi.
V: Nagłówki odpowiedzi HTML, skryptów i plików z uploadu; securityheaders.com.
```http Plik wgrany przez użytkownika
HTTP/2 200
Content-Type: application/pdf
Content-Disposition: attachment; filename="voucher-48213.pdf"
X-Content-Type-Options: nosniff
```
```js Express 5
app.use((req, res, next) => {
  res.set('X-Content-Type-Options', 'nosniff');
  next();
});
// Or: app.use(helmet()) sets it together with other headers
```
X: Serwowanie wszystkich uploadów jako `application/octet-stream` lub `text/plain` bez `nosniff`.
S: MDN: X-Content-Type-Options | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options

[x-frame-options] high
T: Ochrona przed clickjackingiem
D: `Content-Security-Policy: frame-ancestors 'none'` (lub lista dozwolonych domen) blokuje osadzanie strony w obcych ramkach; `X-Frame-Options: DENY` jako uzupełnienie dla starszych klientów.
W: Atakujący osadza Twoją stronę w przezroczystej ramce i nakłania użytkownika do kliknięcia "Zapłać" lub "Usuń konto" na stronie, którą ten widzi jako grę lub konkurs.
W: `frame-ancestors` pozwala wskazać kilka zaufanych domen (np. portal partnera), czego `X-Frame-Options` nie umie; przy obu nagłówkach przeglądarki stosują `frame-ancestors`.
W: Oba mechanizmy działają tylko jako nagłówek HTTP; wersja w `<meta>` jest ignorowana.
V: Nagłówki odpowiedzi; próba osadzenia strony w `<iframe>` na innej domenie (konsola pokaże zablokowanie przez `frame-ancestors`).
```http Nagłówki odpowiedzi
# Default: no framing at all
Content-Security-Policy: frame-ancestors 'none'
X-Frame-Options: DENY

# Booking widget page that a trusted partner may embed
Content-Security-Policy: frame-ancestors 'self' https://partner.example.com
```
X: `X-Frame-Options: ALLOW-FROM`, którego współczesne przeglądarki nie obsługują, więc strona zostaje bez ochrony.
X: Skrypty "frame busting" w JavaScripcie zamiast nagłówka.
S: OWASP: Clickjacking Defense Cheat Sheet | https://cheatsheetseries.owasp.org/cheatsheets/Clickjacking_Defense_Cheat_Sheet.html

[cross-origin-isolation] medium
T: COOP, COEP i CORP, gdy potrzebne
D: Cross-Origin-Opener-Policy, -Embedder-Policy i -Resource-Policy izolują stronę od innych originów (ochrona przed atakami typu Spectre); pełna izolacja jest wymagana m.in. do `SharedArrayBuffer` i precyzyjnych pomiarów pamięci.
W: `Cross-Origin-Opener-Policy: same-origin` zrywa powiązanie z oknami otwartymi z innych domen, co chroni przed atakami przez `window.opener` i wyciekami między kartami; warto go ustawić nawet bez pełnej izolacji.
W: `Cross-Origin-Resource-Policy` na Twoich zasobach (API, obrazy) uniemożliwia innym stronom wczytanie ich do swojego procesu.
W: COEP `require-corp` blokuje zasoby z innych domen bez CORS lub CORP, więc może zepsuć reklamy, mapy i widgety partnerów; `credentialless` jest łagodniejszą alternatywą.
V: Nagłówki odpowiedzi; `self.crossOriginIsolated` w konsoli zwraca `true` przy pełnej izolacji; panel Application > Frames pokazuje status izolacji.
```http Strona wymagająca izolacji (np. edytor z WebAssembly)
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

# On your own static assets and API responses
Cross-Origin-Resource-Policy: same-site
```
```js Weryfikacja w kodzie
if (self.crossOriginIsolated) {
  const shared = new SharedArrayBuffer(1024); // available only when isolated
} else {
  console.warn('Not cross-origin isolated: check COOP and COEP headers');
}
```
X: Włączenie COEP na całym serwisie bez sprawdzenia zasobów zewnętrznych; znikają obrazy z CDN partnerów i ramki płatności.
X: COOP `same-origin` na stronie, która otwiera okno płatności lub logowania przez popup i czeka na `postMessage`; wtedy `same-origin-allow-popups`.
S: web.dev: Making your website cross-origin isolated | https://web.dev/articles/coop-coep

[permissions-policy] medium
T: Nagłówek Permissions-Policy
D: Wyłącza funkcje przeglądarki, których strona nie używa (kamera, mikrofon, geolokalizacja, płatności), także dla osadzonych ramek, a pozostałe ogranicza do zaufanych originów.
W: Gdy skrypt zewnętrzny lub wstrzyknięty kod spróbuje użyć kamery czy geolokalizacji, przeglądarka odmówi bez pytania użytkownika.
W: Ramki reklam i widgetów nie dostaną dostępu do funkcji, których Twoja strona im wprost nie przyznała.
W: Jawna lista używanych funkcji jest dokumentacją dla zespołu i ułatwia audyt prywatności.
V: Nagłówki odpowiedzi; test praktyczny: wywołanie zablokowanego API (np. `navigator.geolocation.getCurrentPosition` w ramce bez `allow`) powinno zakończyć się błędem, a konsola pokaże naruszenie polityki.
```http Nagłówek
# () = disabled everywhere, (self) = this origin only, quoted origins = explicit allow
Permissions-Policy: camera=(), microphone=(), usb=(),
  geolocation=(self), fullscreen=(self),
  payment=(self "https://pay.example.com")
# Sent as a single header line in practice; wrapped here for readability
```
```html Delegacja dla konkretnej ramki
<!-- Map widget may use geolocation, nothing else -->
<iframe src="https://maps.partner.example/embed?hotel=48213"
        allow="geolocation" title="Mapa dojazdu do hotelu" width="600" height="400"></iframe>
```
X: Kopiowanie starych wpisów typu `interest-cohort=()` (FLoC) zamiast dopasowania listy do realnych funkcji.
S: MDN: Permissions-Policy | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy

[referrer-policy] medium
T: Nagłówek Referrer-Policy
D: `strict-origin-when-cross-origin` (domyślne w przeglądarkach) lub bardziej restrykcyjne, ustawione jawnie, żeby pełne adresy z parametrami nie wyciekały do innych serwisów.
W: Adresy bywają wrażliwe: `/rezerwacja/48213?email=jan@example.pl&token=...` w nagłówku `Referer` trafiłby do każdego zewnętrznego skryptu, obrazka czy linku.
W: Przy `strict-origin-when-cross-origin` inne domeny widzą tylko origin (`https://example.pl/`), a Twoja analityka w obrębie serwisu nadal dostaje pełne ścieżki.
W: Jawny nagłówek nie zależy od domyślnych ustawień przeglądarek i klientów osadzonych (webview), które mogą się różnić.
V: Nagłówki odpowiedzi; w Network sprawdź nagłówek `Referer` w żądaniach do zewnętrznych domen.
```http Cały serwis
# Same-origin: full URL; cross-origin HTTPS: origin only; HTTPS to HTTP: nothing
Referrer-Policy: strict-origin-when-cross-origin

# Example: a link from https://example.pl/rezerwacja/48213?email=... to another site
# sends only "Referer: https://example.pl/"
```
```html Wyjątek dla wrażliwej podstrony lub linku
<!-- Booking confirmation page: send no referrer at all -->
<meta name="referrer" content="no-referrer" />

<a href="https://partner.example.com/transfer" referrerpolicy="no-referrer">Zamów transfer z lotniska</a>
```
X: `unsafe-url` ustawione dla wygody analityki partnerów; wysyła pełny adres nawet na HTTP.
X: Dane osobowe lub tokeny w parametrach URL; Referrer-Policy łagodzi skutki, ale nie usuwa problemu.
S: MDN: Referrer-Policy | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy

[new-tab] medium
T: Bezpieczne linki target="_blank"
D: `rel="noopener noreferrer"` przy linkach otwieranych w nowej karcie, a dla `window.open` cecha `noopener`. Współczesne przeglądarki stosują `noopener` domyślnie dla `target="_blank"`, ale jawny atrybut nie zaszkodzi, a `noreferrer` chroni też przed wyciekiem adresu.
W: Bez `noopener` otwarta strona dostaje `window.opener` i może przekierować Twoją kartę na fałszywą stronę logowania (tabnabbing); użytkownik po powrocie nie zauważy podmiany.
W: Domyślne `noopener` nie obejmuje `window.open()` bez odpowiedniej cechy ani starszych przeglądarek i webview.
W: Otwieranie nowych kart bez ostrzeżenia dezorientuje użytkowników czytników ekranu; warto to zasygnalizować w treści lub ikoną z tekstem alternatywnym.
V: Wyszukaj `target="_blank"` i `window.open(` w kodzie; lintery (np. ESLint `react/jsx-no-target-blank`) wychwytują brak `rel`.
```html Link do serwisu zewnętrznego
<a href="https://www.gov.pl/web/dyplomacja/grecja" target="_blank" rel="noopener noreferrer">
  Informacje MSZ dla podróżujących
  <span class="visually-hidden">(otwiera się w nowej karcie)</span>
</a>
```
```js window.open
// Bad: the new page gets window.opener and can redirect this tab
window.open('https://partner.example.com/ubezpieczenie', '_blank');

// Good: with noopener the call returns null, the new page has no handle to this tab
window.open('https://partner.example.com/ubezpieczenie', '_blank', 'noopener,noreferrer');
```
X: Dodanie `noreferrer` do linków partnerskich, które rozliczają się po nagłówku `Referer`, bez uzgodnienia innego sposobu atrybucji.
S: OWASP: HTML5 Security Cheat Sheet | https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html

[session-cookie-flags] high
T: Flagi Secure, HttpOnly, SameSite
D: Cookie sesyjne z `Secure` (tylko HTTPS), `HttpOnly` (niedostępne dla JS) i `SameSite=Lax` lub `Strict` (ochrona przed CSRF), najlepiej z prefiksem `__Host-` i `Path=/`.
W: `HttpOnly` sprawia, że nawet udany atak XSS nie odczyta identyfikatora sesji przez `document.cookie` i nie wyśle go atakującemu.
W: `Secure` gwarantuje, że cookie nie poleci otwartym tekstem po przypadkowym żądaniu `http://`.
W: `SameSite=Lax` blokuje wysyłanie cookie przy żądaniach POST i `fetch` z obcych stron, więc ukryty formularz na innej domenie nie zmieni danych rezerwacji.
W: Prefiks `__Host-` wymusza `Secure`, `Path=/` i brak `Domain`, więc subdomena (np. przejęty blog) nie nadpisze cookie sesji.

# After logout: overwrite with the same attributes and expire immediately
Set-Cookie: __Host-session=; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=0
```

  path: '/',

});
```
X: `SameSite=None` bez potrzeby (np. "bo tak działało"); wtedy ochrona przed CSRF znika.
X: Traktowanie `SameSite` jako jedynej ochrony przed CSRF przy operacjach zmieniających stan przez GET.
S: MDN: Set-Cookie | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie
