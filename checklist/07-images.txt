[alt-text] critical
T: Sensowny tekst alternatywny
D: Każdy `<img>` ma `alt`: opis treści lub funkcji dla obrazów informacyjnych, pusty `alt=""` dla dekoracyjnych. Brak atrybutu sprawia, że czytnik ekranu odczytuje nazwę pliku lub adres.
W: Bez `alt` czytnik ekranu ogłosi np. "IMG_4821 kropka jpg, grafika"; osoba niewidoma nie dowie się, że zdjęcie pokazuje basen hotelu ani że ikona to przycisk "Szukaj".
W: Obraz będący jedyną treścią linku lub przycisku bez `alt` daje kontrolkę bez nazwy; to błąd WCAG 1.1.1 (poziom A), wymaganego m.in. przez European Accessibility Act.
W: Google używa `alt` do zrozumienia obrazu i jego kontekstu, więc dobry opis wspiera też wyszukiwanie grafik.
W: Tekst alternatywny wyświetla się, gdy obraz się nie pobierze (słaby zasięg, zablokowane obrazy), więc treść nadal jest zrozumiała.
V: axe lub Lighthouse (reguła `image-alt`), przegląd z czytnikiem ekranu (NVDA, VoiceOver); w DevTools panel Accessibility pokazuje obliczoną nazwę obrazu.
```html Decyzja o alt w praktyce
<!-- Informative: describe what matters in this context -->
<img src="/img/hotel-kreta-basen.webp" alt="Basen bez brodzika z widokiem na morze, hotel Aegean Blue" width="800" height="533" />

<!-- Functional: describe the action, not the picture -->
<a href="/"><img src="/logo.svg" alt="Wakacje.pl: strona główna" width="140" height="32" /></a>
<button type="submit"><img src="/icons/search.svg" alt="Szukaj" width="20" height="20" /></button>

<!-- Decorative: empty alt, screen reader skips it -->
<img src="/img/wave-divider.svg" alt="" width="1200" height="40" />

<!-- Image of text: repeat the text -->
<img src="/promo/first-minute.png" alt="First Minute: do 30% taniej, rezerwuj do 31 stycznia" width="600" height="200" />
```
X: Alt typu "obrazek", "zdjęcie" lub nazwa pliku; czytnik i tak ogłasza, że to grafika.
X: Powtarzanie w `alt` tego samego tekstu, który stoi obok obrazu w podpisie lub nagłówku karty.
X: Pominięcie atrybutu zamiast `alt=""` przy dekoracjach; to nie to samo.
S: W3C WAI: An alt Decision Tree | https://www.w3.org/WAI/tutorials/images/decision-tree/

[figure-figcaption] medium
T: figure i figcaption dla podpisów
D: Obraz z podpisem umieść w `<figure>` z `<figcaption>`; podpis jest wtedy semantycznie powiązany z obrazem i staje się dostępną nazwą całej figury.
W: Czytnik ekranu ogłasza figurę i jej podpis razem, więc użytkownik wie, że "Widok z balkonu pokoju typu Superior" opisuje właśnie to zdjęcie, a nie sąsiedni akapit.
W: Zwykły `<p>` pod obrazem jest tylko wizualnie blisko; po zmianie układu (np. na mobile) lub w trybie czytania powiązanie znika.
W: `<figure>` nadaje się też do wykresów, fragmentów kodu i cytatów, dając spójny wzorzec dla całego CMS.
V: Przegląd DOM galerii i artykułów; w panelu Accessibility w DevTools figura powinna mieć nazwę z `figcaption`.
```html
<figure class="gallery-item">
  <img
    src="/img/hotel-kreta-pokoj-superior.webp"
    alt="Dwuosobowy pokój z balkonem i widokiem na zatokę"
    width="1200" height="800" loading="lazy" />
  <figcaption>Pokój Superior z widokiem na morze, dopłata 120 zł za noc.</figcaption>
</figure>
```
X: Kopiowanie całego podpisu do `alt`; `alt` opisuje obraz, podpis dodaje kontekst.
X: Używanie `<figure>` dla każdego obrazka, także dekoracyjnych ikon bez podpisu.
S: MDN: The figure element | https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/figure

[filename-quality] low
T: Opisowe nazwy plików
D: `hotel-kreta-basen.webp` zamiast `IMG_1234.jpg`: małe litery, myślniki, kilka opisowych słów, bez polskich znaków i spacji. Pomaga w wyszukiwaniu grafik.
W: Google wymienia nazwę pliku jako jeden z sygnałów o tematyce obrazu w Grafice Google; `IMG_1234.jpg` nie mówi nic.
W: Polskie znaki i spacje w adresach są kodowane jako `%C4%85` czy `%20`, co psuje czytelność linków i bywa źródłem błędów 404 po migracjach.
W: Opisowe nazwy ułatwiają pracę redakcji: łatwiej znaleźć i podmienić zdjęcie w CMS lub repozytorium.
V: Przegląd nazw plików w CMS i repozytorium; crawler z filtrem obrazów pokaże nazwy typu `IMG_`, `DSC_`, `screenshot`.
```ts Normalizacja nazwy przy uploadzie
// Turn "Hotel Kreta, basen (1).JPG" into "hotel-kreta-basen-1.jpg"
export function toImageSlug(fileName: string): string {
  const dot = fileName.lastIndexOf('.');
  const base = dot > 0 ? fileName.slice(0, dot) : fileName;
  const ext = dot > 0 ? fileName.slice(dot + 1).toLowerCase() : 'jpg';
  const slug = base
    .normalize('NFD')
    .replace(/[̀-ͯ]/g, '') // strip diacritics
    .replace(/ł/g, 'l').replace(/Ł/g, 'L')
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');
  return `${slug || 'image'}.${ext}`;
}
```
X: Upychanie słów kluczowych w nazwie (`tanie-wakacje-grecja-tanie-hotele-grecja.jpg`).
S: Google: Image SEO best practices | https://developers.google.com/search/docs/appearance/google-images

[broken-images] high
T: Brak niedziałających obrazów
D: Obrazy zwracające 404 psują wygląd i zaufanie. Waliduj ścieżki w buildzie, testuj kluczowe szablony i monitoruj błędy na produkcji.
W: Pusta ramka w miejscu zdjęcia hotelu wygląda jak porzucona oferta; użytkownik traci zaufanie dokładnie w momencie decyzji o zakupie.
W: Każdy błędny adres to zbędne zapytanie i często przesunięcie układu, bo przeglądarka nie zna proporcji brakującego obrazu.
W: Obrazy często znikają po migracji CMS, zmianie bucketu lub wygaśnięciu linków z zewnętrznego API dostawcy ofert; bez monitoringu nikt tego nie zauważy.
V: Crawler (np. Screaming Frog) z raportem obrazów 4xx, filtr Img i kolumna Status w Network; automatycznie test end-to-end jak niżej.
```ts Playwright: test braku zepsutych obrazów
import { test, expect } from '@playwright/test';

for (const path of ['/', '/wakacje/grecja', '/hotel/aegean-blue']) {
  test(`no broken images on ${path}`, async ({ page }) => {
    await page.goto(path);
    await page.evaluate(() => window.scrollTo(0, document.body.scrollHeight)); // trigger lazy images
    await page.waitForLoadState('networkidle');
    const broken = await page.$$eval('img', (imgs) =>
      imgs
        .filter((img) => img.complete && img.naturalWidth === 0)
        .map((img) => img.currentSrc || img.src),
    );
    expect(broken).toEqual([]);
  });
}
```
X: Testowanie tylko strony głównej, a pomijanie szablonów ofert z obrazami z zewnętrznych API.

[error-images] low
T: Obsługa błędów ładowania obrazów
D: Przy błędzie pokaż placeholder lub obraz zastępczy (`onerror` z `this.onerror = null`, żeby uniknąć pętli) zamiast ikony zepsutego obrazka.
W: Ikona zepsutego obrazka i rozjechany układ karty wyglądają na błąd całego serwisu; neutralny placeholder w kolorach marki utrzymuje spójny wygląd.
W: Obrazy z zewnętrznych źródeł (systemy touroperatorów, CDN partnerów) bywają niedostępne niezależnie od Ciebie.
W: Bez wyzerowania handlera brak pliku zastępczego wywołuje nieskończoną pętlę zapytań.
V: Zablokuj adres obrazu w DevTools (Network request blocking) i sprawdź, czy karta pokazuje placeholder i zachowuje wymiary.
```html Czysty HTML
<img
  src="https://cdn.partner.example/hotels/48213/main.jpg"
  alt="Hotel Aegean Blue, widok z plaży"
  width="400" height="300"
  onerror="this.onerror = null; this.src = '/img/placeholder-hotel.svg';" />
```
```tsx React
import { useState } from 'react';

const FALLBACK = '/img/placeholder-hotel.svg';

export function HotelImage({ src, alt }: { src: string; alt: string }) {
  const [current, setCurrent] = useState(src);
  return (
    <img
      src={current}
      alt={alt}
      width={400}
      height={300}
      // Switch only once, so a missing fallback cannot cause a loop
      onError={() => setCurrent((prev) => (prev === FALLBACK ? prev : FALLBACK))}
    />
  );
}
```
X: Zastępowanie obrazu pustym `alt=""` po błędzie; informacja o treści znika także dla czytników.

@cl-group Formaty
sources: web.dev: Choose the right image format | https://web.dev/articles/choose-the-right-image-format

[modern-format] high
T: Nowoczesne formaty (WebP, AVIF)
D: Zdjęcia serwuj jako AVIF lub WebP zamiast JPEG i PNG. WebP jest zwykle o 25-35% mniejszy od JPEG, AVIF często o 40-50%. Oba działają we wszystkich aktualnych przeglądarkach.
W: Obrazy to zwykle największa część wagi strony; zmniejszenie zdjęć o jedną trzecią skraca ładowanie listy ofert na słabym LTE o sekundy.
W: Mniejszy obraz hero to szybsze LCP, które Google wykorzystuje w ocenie jakości strony (próg 2,5 s dla 75. percentyla).
W: Mniej przesłanych bajtów to niższe rachunki za transfer CDN i mniejsze zużycie pakietu danych u użytkowników mobilnych.
V: Lighthouse (sekcja o dostarczaniu obrazów), kolumna Type w Network; porównaj rozmiary przed i po konwersji.
```js scripts/convert-images.mjs
// Generate AVIF and WebP next to every JPEG/PNG source (sharp 0.34)
import { glob } from 'node:fs/promises';
import sharp from 'sharp';

for await (const file of glob('src/assets/photos/**/*.{jpg,jpeg,png}')) {
  const base = file.replace(/\.(jpe?g|png)$/i, '');
  const img = sharp(file).rotate(); // apply EXIF orientation; metadata is stripped on output
  await Promise.all([
    img.clone().avif({ quality: 50, effort: 4 }).toFile(`${base}.avif`),
    img.clone().webp({ quality: 75 }).toFile(`${base}.webp`),
  ]);
  console.log('converted', file);
}
```
X: Konwersja logo, ikon i zrzutów z ostrymi krawędziami do stratnego formatu zamiast SVG lub bezstratnego WebP.
X: Serwowanie AVIF bez fallbacku tam, gdzie obraz trafia też do maili lub starych webview.

[webp-format] high
T: WebP z fallbackiem
D: WebP przez `<picture>` lub negocjację po nagłówku `Accept` na CDN, z JPEG/PNG jako zapasem dla nielicznych starych przeglądarek i klientów spoza przeglądarki.
W: WebP działa we wszystkich głównych przeglądarkach od Safari 14 (2020), ale obrazy z serwisu trafiają też do klientów pocztowych, czytników RSS i podglądów linków, które nie zawsze go obsługują.
W: Fallback w `<img>` sprawia, że przeglądarka bez wsparcia po prostu pobierze JPEG, zamiast pokazać pusty obszar.
W: Negocjacja po `Accept` pozwala zachować jeden adres obrazu w HTML; wymaga jednak `Vary: Accept`, inaczej cache CDN poda WebP klientowi, który go nie rozumie.
V: Network: kolumna Type i nagłówki odpowiedzi (`Content-Type`, `Vary`); test w przeglądarce lub kliencie bez WebP, np. przez `curl` z nagłówkiem `Accept: image/jpeg`.
```html Fallback w znacznikach
<picture>
  <source srcset="/img/hotel-kreta-basen.webp" type="image/webp" />
  <img src="/img/hotel-kreta-basen.jpg" alt="Basen hotelu przy plaży" width="1200" height="800" />
</picture>
```
```http Negocjacja na CDN
GET /img/hotel-kreta-basen.jpg HTTP/2
Accept: image/avif,image/webp,image/apng,*/*;q=0.8

HTTP/2 200
Content-Type: image/webp
Vary: Accept
Cache-Control: public, max-age=31536000, immutable
```
X: Brak `Vary: Accept` przy negocjacji formatu; cache pośredni miesza wersje.

[avif-format] medium
T: AVIF dla nowoczesnych przeglądarek
D: AVIF daje zwykle najlepszą kompresję zdjęć, ale koduje się wolniej niż WebP. Umieść go jako pierwsze źródło w `<picture>` przed WebP lub pozwól wybrać go CDN obrazów.
W: Przy tej samej jakości AVIF bywa wyraźnie mniejszy od WebP, szczególnie dla dużych zdjęć z gładkimi gradientami (niebo, morze), czyli typowych zdjęć wakacyjnych.
W: Wszystkie aktualne przeglądarki (Chrome, Firefox, Safari 16+, Edge 121+) obsługują AVIF, więc zysk dotyczy większości użytkowników.
W: Kodowanie AVIF jest kilka razy wolniejsze, dlatego konwertuj w buildzie lub z cache na CDN, a nie przy każdym żądaniu.
V: Network w Chrome: obraz powinien mieć typ `avif`; porównaj rozmiar z wersją WebP i oceń jakość wizualnie przy 100% powiększenia.
```html Kolejność źródeł
<picture>
  <!-- The browser takes the first source it supports -->
  <source srcset="/img/hero-santorini.avif" type="image/avif" />
  <source srcset="/img/hero-santorini.webp" type="image/webp" />
  <img src="/img/hero-santorini.jpg" alt="Białe domy Santorini nad zatoką o zachodzie słońca"
       width="1600" height="900" fetchpriority="high" />
</picture>
```
```css Tło w CSS
.promo-banner {
  background-image: image-set(
    url("/img/promo-bg.avif") type("image/avif"),
    url("/img/promo-bg.webp") type("image/webp"),
    url("/img/promo-bg.jpg") type("image/jpeg")
  );
  background-size: cover;
}
```
X: Zbyt niska jakość AVIF (artefakty rozmycia na twarzach i tekstach) w pogoni za rozmiarem.

[picture-element] high
T: picture z fallbackiem img
D: `<picture>` z elementami `<source type="image/avif">` i `<source type="image/webp">` (lub `media` dla innego kadru), a jako ostatnie dziecko zawsze `<img>` z `alt`, wymiarami i źródłem zapasowym.
W: `<img>` jest tym, co faktycznie się renderuje: to on niesie `alt`, `width`/`height`, `loading` i `fetchpriority`; `<source>` tylko podmienia plik.
W: Bez `<img>` w środku `<picture>` nic się nie wyświetli, nawet w przeglądarce obsługującej wszystkie formaty.
W: Przeglądarka wybiera pierwsze pasujące źródło, więc kolejność AVIF, WebP, JPEG decyduje o tym, ile bajtów zostanie pobranych.
V: Przegląd znaczników `<picture>`; w konsoli `$0.currentSrc` na zaznaczonym `<img>` pokazuje, które źródło zostało wybrane.
```html Formaty i art direction
<picture>
  <!-- Mobile: tighter square crop -->
  <source media="(max-width: 640px)" type="image/avif"
          srcset="/img/hotel-mobile-600.avif 600w, /img/hotel-mobile-900.avif 900w"
          sizes="100vw" width="900" height="900" />
  <!-- Desktop: wide crop -->
  <source type="image/avif"
          srcset="/img/hotel-1200.avif 1200w, /img/hotel-1800.avif 1800w"
          sizes="(max-width: 1280px) 100vw, 1280px" />
  <source type="image/webp"
          srcset="/img/hotel-1200.webp 1200w, /img/hotel-1800.webp 1800w"
          sizes="(max-width: 1280px) 100vw, 1280px" />
  <img src="/img/hotel-1200.jpg" alt="Hotel nad zatoką z prywatną plażą"
       width="1800" height="1012" />
</picture>
```
X: Stawianie `alt` na `<picture>` lub `<source>`; działa tylko na `<img>`.
X: Brak `type` w `<source>`, przez co przeglądarka może wybrać format, którego nie obsługuje.
S: MDN: The picture element | https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/picture

[progressive-jpeg] low
T: Progresywny JPEG
D: Progresywne kodowanie pokazuje najpierw całą rozmytą wersję obrazu, a potem ją wyostrza, co poprawia odczuwalną szybkość dużych zdjęć tam, gdzie wciąż serwujesz JPEG.
W: Na wolnym łączu użytkownik od razu widzi kompozycję zdjęcia zamiast obrazu ładowanego paskami od góry.
W: Przy dużych zdjęciach progresywny JPEG (z mozjpeg) jest często nawet nieco mniejszy od bazowego.
W: JPEG pozostaje fallbackiem w `<picture>` i formatem dla maili oraz podglądów linków, więc warto zadbać i o niego.
V: ImageMagick `identify -verbose` (pole `Interlace: JPEG`) lub ustawienia narzędzia do kompresji; wizualnie przy throttlingu "Slow 3G".
```js sharp: progresywny JPEG
import sharp from 'sharp';

await sharp('src/hero-santorini.jpg')
  .resize({ width: 1600, withoutEnlargement: true })
  .jpeg({ quality: 80, progressive: true, mozjpeg: true }) // mozjpeg: better compression
  .toFile('public/img/hero-santorini.jpg');
```
```bash Weryfikacja
identify -verbose public/img/hero-santorini.jpg | grep -i interlace
# Interlace: JPEG  -> progressive
# Interlace: None  -> baseline

# Check all JPEG files at once
identify -format "%f %[interlace]\n" public/img/*.jpg
```
X: Traktowanie progresywnego JPEG jako zamiennika AVIF lub WebP; to tylko poprawa fallbacku.

[image-optimization] high
T: Optymalizacja wszystkich obrazów
D: Każdy obraz przechodzi przez pipeline: właściwy format, wymiary dopasowane do wyświetlania, kompresja, usunięte metadane. Najlepiej automatycznie (CDN obrazów, `next/image`, sharp w buildzie), a nie ręcznie.
W: Ręczna optymalizacja przestaje działać z pierwszym zdjęciem wgranym przez redakcję prosto z aparatu (6000 px, 8 MB); automat działa na każdym uploadzie.
W: Metadane EXIF potrafią zawierać współrzędne GPS, model aparatu i datę; ich usunięcie zmniejsza plik i chroni prywatność autorów.
W: Spójny pipeline daje przewidywalne LCP i wagę stron, co ułatwia utrzymanie budżetów wydajności.
V: Lighthouse (sekcja obrazów), rozmiary w Network; sprawdź, czy obraz wgrany przez CMS trafia na stronę już przetworzony.
```ts next.config.ts (Next.js 16)
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  images: {
    formats: ['image/avif', 'image/webp'], // AVIF first, WebP fallback via Accept header
    qualities: [60, 75],                   // required allowlist since Next.js 16
    deviceSizes: [640, 828, 1080, 1280, 1920],
    remotePatterns: [new URL('https://cdn.partner.example/hotels/**')],
    minimumCacheTTL: 60 * 60 * 24 * 30,    // 30 days
  },
};

export default nextConfig;
```
X: Optymalizacja obrazów w repozytorium, ale nie tych z CMS i zewnętrznych API, które stanowią większość.

[optimized] high
T: Obrazy zoptymalizowane pod szybkie ładowanie
D: Połączenie formatu, rozmiaru, kompresji i priorytetu ładowania; obrazy to zwykle największa część wagi strony, więc tu zwykle jest największy zysk.
W: Obraz jest elementem LCP na większości stron; jego optymalizacja to najczęściej najprostsza droga do zmieszczenia się w 2,5 s.
W: Lista 30 ofert z niezoptymalizowanymi miniaturami to kilka MB, które użytkownik mobilny pobiera, zanim w ogóle zacznie przewijać.
W: Wolniejsze strony mają wyższy współczynnik odrzuceń; w turystyce użytkownik porównuje oferty w kilku kartach i zamyka tę, która ładuje się najdłużej.
V: Network posortowany po rozmiarze z filtrem Img; poniższy snippet w konsoli wypisze największe obrazy.
```js Snippet do konsoli DevTools
// List images over 150 KB with transfer size and rendered vs natural width
// (cross-origin images need Timing-Allow-Origin to report transferSize)
const imgs = [...document.images];
performance.getEntriesByType('resource')
  .filter((e) => e.initiatorType === 'img' && e.transferSize > 150_000)
  .map((e) => {
    const el = imgs.find((i) => i.currentSrc === e.name);
    return {
      url: e.name,
      kb: Math.round(e.transferSize / 1024),
      natural: el?.naturalWidth,
      rendered: el ? Math.round(el.clientWidth * devicePixelRatio) : null,
    };
  })
  .forEach((row) => console.log(row));
```
X: Optymalizacja jednego wymiaru (np. formatu) przy ignorowaniu reszty: AVIF w 4000 px nadal jest za duży.

[image-compression] high
T: Kompresja bez widocznej straty jakości
D: Jakość ok. 75-85 dla JPEG i WebP (dla AVIF zwykle niższa wartość liczbowa, ok. 45-60) nie daje widocznej różnicy, a znacząco zmniejsza plik. Porównuj wizualnie, np. w Squoosh.
W: Różnica między jakością 100 a 80 bywa dwu-, trzykrotna w rozmiarze, a na ekranie telefonu praktycznie niewidoczna.
W: Skale jakości różnych enkoderów nie są porównywalne: "50" w AVIF to nie to samo co "50" w JPEG, dlatego decyduj na podstawie podglądu, a nie samej liczby.
W: Zbyt agresywna kompresja daje artefakty na twarzach, tekstach i gradientach nieba, co obniża postrzeganą jakość oferty.
V: Porównanie wersji w Squoosh (widok podzielony), rozmiary plików; przegląd przy 100% powiększenia na zdjęciach z twarzami i tekstem.
```bash Kompresja z linii poleceń
# WebP at quality 80, metadata removed
cwebp -q 80 -metadata none hotel-kreta.jpg -o hotel-kreta.webp
```

```js scripts/check-image-budget.mjs
import { glob, stat } from 'node:fs/promises';

const LIMITS_KB = { hero: 400, thumb: 30, icon: 50, default: 200 };
const failures = [];

for await (const file of glob('public/img/**/*.{avif,webp,jpg,png,svg}')) {
  const kind = Object.keys(LIMITS_KB).find((k) => file.includes(`/${k}`)) ?? 'default';
  const kb = (await stat(file)).size / 1024;
  if (kb > LIMITS_KB[kind]) failures.push(`${file}: ${kb.toFixed(0)} KB > ${LIMITS_KB[kind]} KB`);
}

if (failures.length) {
  console.error(failures.join('\n'));
  process.exit(1);
}
```
