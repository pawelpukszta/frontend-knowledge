# Baza wiedzy FE

Interactive front-end interview prep app (mid / senior): a topic library, interview questions with model answers, a quiz, flashcards and a front-end checklist. Every topic links to its sources.

> **Proof of concept.** This is the original single-file version of the app, kept as the `poc-v0` tag. It is frozen: the project continues as a React + TypeScript desktop app (tinyjs) and PWA on the `main` branch.

## Open it

Open `index.html` in any browser. It is a single self-contained file. Fonts (Google Fonts) and syntax highlighting (Prism from cdnjs) load from the network; without a connection the app still works with fallback fonts and plain code blocks.

## Structure

```
content/        Topic sources, one file per category (Polish content)
checklist/      Front-end checklist rules (Polish), based on frontendchecklist.io (MIT)
build/parse.py  Parses content/*.txt into data.json
build/build.py  Injects data.json into template.html and writes index.html
build/template.html  App shell: styles, layout and all app logic
index.html      Standalone page (the one to open), generated by the build
```

## Adding or editing a topic

Edit the matching `content/NN-<category>.txt` file. Format:

```
@topic unique-topic-id
title: Topic title
level: mid | senior
tags: tag1, tag2
summary: One or two sentences shown as the TL;DR.

::: body
Markdown (lists, tables, `code`, **bold**).

::: flow
Step one > Step two > Step three

::: analogy
Optional everyday analogy.

::: code ts Optional example title
// code block; language: js, ts, tsx, html, css, json, http, graphql, md

::: pitfalls
- Common mistake

::: qa
Q: Interview question?
A: Model answer (Markdown, may span several lines).

::: sources
- Source title | https://example.com/page
```

Quiz questions go at the end of a category file:

```
@quiz
Q: Question text
- wrong option
+ correct option
- wrong option
E: Short explanation.
T: topic-id-it-links-to
```

## Checklist rules

The checklist (`checklist/*.txt`) is based on the [Front-End Checklist](https://frontendchecklist.io/) by David Dias (MIT license), translated to Polish and extended with links to standards. Format:

```
@cl-category accessibility          # must match the frontendchecklist.io category slug
name: Dostępność
desc: Short category description.
sources: Title | https://url ; Title | https://url

@cl-group Group name
sources: Title | https://url

[rule-slug] critical|high|medium|low
T: Rule title
D: What the rule requires (inline Markdown).
W: Why it matters, one reason per line (2-4 lines)
V: How to verify it.
(fenced code blocks: three backticks + language + optional title, e.g. "css Dobrze")
X: Common mistake, one per line (optional)
S: Optional extra source | https://url
```

Allowed code block languages: `html css scss js ts tsx jsx json http bash yaml xml md txt graphql`. Keep `[slug] priority` lines unchanged when editing existing rules, write 2-4 `W:` lines per rule and keep code comments in English.

The link to the original rule (`https://frontendchecklist.io/rules/{category}/{slug}`) is generated automatically. Progress in the app is stored per browser (localStorage).

Every topic needs at least one source, and every quiz question must point to an existing topic id; the parser fails otherwise.

## Rebuild

```
pip install markdown
python3 build/build.py
```

The build also fails if the output contains an em dash.
