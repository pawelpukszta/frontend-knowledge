@cl-group Animacje i ruch
sources: W3C Understanding 2.3.1: Three Flashes or Below Threshold | https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html ; MDN: prefers-reduced-motion | https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion

[flashing-content] critical
T: Brak treści migających częściej niż 3 razy na sekundę
D: Treść nie może błyskać ani migotać więcej niż 3 razy w ciągu sekundy, chyba że błyski są małe i poniżej progów ogólnego oraz czerwonego błysku. To kryterium WCAG 2.3.1 (poziom A), którego naruszenie grozi realnym zagrożeniem zdrowia: napadem padaczki fotogennej.
W: Padaczka fotogenna dotyczy ok. 3% osób chorych na padaczkę (dane Epilepsy Foundation); napad mogą wywołać już sekundy migotania, a strona nie daje "drugiego podejścia".
W: W 1997 roku jeden odcinek anime "Pokemon" z szybko migającą czerwono-niebieską sceną sprawił, że kilkaset dzieci w Japonii trafiło do szpitala; nasycona czerwień jest szczególnie niebezpieczna.
W: Przycisk pauzy nie rozwiązuje problemu: migotanie szkodzi, zanim użytkownik zdąży zareagować, dlatego kryterium obowiązuje także dla autoodtwarzanych wideo i reklam.
V: Przejrzyj animacje, wideo, GIF-y i efekty "flash" przy promocjach; podejrzane materiały sprawdź analizatorem błysków (PEAT, Harding FPA). W kodzie szukaj animacji z cyklem krótszym niż ok. 333 ms, które zmieniają jasność lub kolor dużych obszarów.
```css Źle
/* "Last minute" badge flashes 5 times per second */
.badge-hot { animation: flash 200ms steps(1) infinite; }
@keyframes flash {
  50% { background: #ff0000; color: #ffffff; }
}
```
```css Dobrze
/* Slow, subtle pulse: one cycle per 2 s, opacity only, stops after 3 runs */
.badge-hot { animation: pulse 2s ease-in-out 3; }
@keyframes pulse {
  50% { opacity: 0.7; }
}
@media (prefers-reduced-motion: reduce) {
  .badge-hot { animation: none; }
}
```
X: Efekt stroboskopu w wideo hero lub banerze reklamowym; za treści osadzone z sieci reklamowych też odpowiadasz.
X: Testowanie tylko na telefonie; na dużym monitorze ten sam błysk zajmuje znacznie większą część pola widzenia.
S: W3C Understanding 2.3.1 | https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html

[reduced-motion] high
T: Respektuj preferencję ograniczenia ruchu
D: Użytkownicy z zaburzeniami przedsionkowymi (błędnika) włączają w systemie opcję "ogranicz ruch". Media query `prefers-reduced-motion: reduce` powinna wyłączać lub łagodzić duże animacje, paralaksę, autoodtwarzane efekty i animowane przejścia między widokami.
W: Ruch na ekranie, zwłaszcza przesuwanie i skalowanie dużych obszarów, wywołuje u osób z zaburzeniami przedsionkowymi zawroty głowy, nudności i migrenę, które potrafią trwać godzinami po zamknięciu strony.
W: Ustawienie istnieje w iOS, Androidzie, macOS i Windows, a przeglądarki przekazują je do CSS i JS, więc obsługa kosztuje kilka linii kodu.
W: WCAG 2.3.3 (AAA) wymaga możliwości wyłączenia animacji wywołanych interakcją, a 2.2.2 (A) pauzy dla ruchu trwającego automatycznie dłużej niż 5 sekund.
V: Włącz emulację `prefers-reduced-motion` w DevTools (Rendering) i sprawdź, czy duże animacje znikają; sprawdź też animacje sterowane z JS (Web Animations API, Motion, GSAP) i View Transitions.
```css Ruch tylko na życzenie
/* Motion is opt-in: only users without the preference get it */
@media (prefers-reduced-motion: no-preference) {
  .offer-card { transition: transform 300ms ease; }
  .offer-card:hover { transform: translateY(-4px); }
}

@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) { animation: none !important; }
}
```
```ts Animacje w JS
const reduceMotion = window.matchMedia("(prefers-reduced-motion: reduce)");

export function revealHero(el: HTMLElement) {
  if (reduceMotion.matches) return; // show the final state immediately
  el.animate(
    [{ opacity: 0, transform: "scale(0.96)" }, { opacity: 1, transform: "none" }],
    { duration: 400, easing: "ease-out" },
  );
}
```
X: Ograniczenie ruchu nie oznacza usunięcia wszystkiego: płynna zmiana koloru lub przezroczystości jest zwykle bezpieczna; usuwaj przesunięcia, skalowanie, obroty i paralaksę.
X: Obsługa preferencji tylko w CSS, z pominięciem bibliotek JS i autoodtwarzanego wideo w tle.
S: W3C Understanding 2.3.3: Animation from Interactions | https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html

[parallax-effects] medium
T: Zapewnij alternatywę dla efektów paralaksy
D: Paralaksa i ruch tła przy przewijaniu wywołują u części osób zawroty głowy i nudności. Przy `prefers-reduced-motion: reduce` warstwy powinny przewijać się razem z treścią, a efekt nie może być jedynym sposobem pokazania informacji.
W: Różna prędkość warstw podczas przewijania to dokładnie ten rodzaj ruchu, który najczęściej wywołuje objawy u osób z zaburzeniami przedsionkowymi; paralaksa jest przykładem omawianym wprost w WCAG 2.3.3.
W: Paralaksa liczona w JS w zdarzeniu `scroll` obciąża główny wątek i szarpie na słabszych telefonach; scroll-driven animations w CSS działają poza głównym wątkiem.
W: Treść ujawniana dopiero przez efekt (tekst wjeżdżający przy przewijaniu) musi być widoczna także wtedy, gdy animacja jest wyłączona.
V: Sprawdź stronę z emulacją reduced motion; tło nie powinno się poruszać niezależnie od treści, a cała treść musi być widoczna.
```css Paralaksa tylko bez reduced motion
.hero { position: relative; overflow: clip; }
.hero__bg { position: absolute; inset: -10% 0; background: url("/img/santorini.avif") center / cover; }

/* Parallax only for users who did not ask for less motion */
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: scroll()) {
    .hero__bg {
      animation: hero-parallax linear both;
      animation-timeline: scroll(root);
      animation-range: 0 100vh;
    }
    @keyframes hero-parallax { to { transform: translateY(20%); } }
  }
}
```
X: Ciężki handler `scroll` z `getBoundingClientRect()` w każdej klatce zamiast animacji sterowanej przewijaniem.
X: Tekst nagłówka ukryty (`opacity: 0`) do momentu odpalenia animacji; przy wyłączonym ruchu nigdy się nie pojawia.

[scrolljacking] medium
T: Nie przejmuj natywnego przewijania (scrolljacking)
D: Nie zmieniaj prędkości ani kierunku przewijania i nie zamieniaj kółka myszy w przeskoki między sekcjami. Takie nadpisywanie łamie oczekiwania użytkowników, utrudnia nawigację klawiaturą i czytnikami ekranu oraz psuje gesty na urządzeniach dotykowych.
W: Użytkownik traci kontrolę: jeden ruch kółkiem przenosi go o cały ekran, więc nie przeczyta treści we własnym tempie; osoby z drżeniem rąk lub korzystające z trackballa trafiają w niewłaściwe sekcje.
W: Przechwycone zdarzenie `wheel` z `preventDefault()` często psuje przewijanie Spacją, PageDown i komendami czytników ekranu, a stopka z danymi kontaktowymi bywa nieosiągalna.
W: Nasłuchiwanie `wheel` lub `touchmove` z `passive: false` blokuje przewijanie realizowane przez kompozytor i powoduje szarpanie na słabszych urządzeniach.
V: Przewiń stronę kółkiem, touchpadem, klawiaturą (Space, PageDown) i gestem na telefonie; zachowanie musi być natywne. W DevTools (Elements, zakładka Event Listeners) poszukaj handlerów `wheel` i `touchmove` wywołujących `preventDefault()`.
```js Źle
// Hijacks the wheel and jumps between full-screen sections
window.addEventListener("wheel", (e) => {
  e.preventDefault();
  goToSection(current + Math.sign(e.deltaY));
}, { passive: false });
```
```css Dobrze
/* Native scrolling with gentle snapping; the user keeps full control */
.destinations {
  display: flex;
  gap: 1rem;
  overflow-x: auto;
  scroll-snap-type: x proximity;
}
.destinations > li { flex: 0 0 min(80%, 22rem); scroll-snap-align: start; }
```
X: `scroll-snap-type: y mandatory` na całej stronie; sekcja dłuższa niż ekran staje się częściowo nieosiągalna.
X: Infinite scroll bez przycisku "Pokaż więcej" i bez dostępu do stopki.

[anchor-smooth-scroll] low
T: Płynne przewijanie do kotwic tylko bez reduced motion
D: `scroll-behavior: smooth` jest przyjemne, ale powinno być wyłączone dla osób, które ograniczają ruch. Najprościej ustawić je wewnątrz `@media (prefers-reduced-motion: no-preference)`, a w JS dobierać `behavior` według tej samej preferencji.
W: Płynny przejazd przez kilka ekranów treści to dokładnie ten ruch, który osoby z zaburzeniami przedsionkowymi wyłączają w systemie.
W: Ustawienie w CSS działa też dla `scrollIntoView()` i `scrollTo()` wywołanych bez opcji `behavior`, więc jedna reguła kontroluje całą stronę; jawne `behavior: "smooth"` w JS ją omija.
W: Długa animacja przewijania opóźnia dotarcie do treści i koliduje z użytkownikiem, który w tym czasie sam zaczyna przewijać.
V: Kliknij link do kotwicy z emulacją reduced motion; przeskok powinien być natychmiastowy, a cel nie może chować się pod przyklejonym nagłówkiem.
```css
/* Smooth scrolling only for users who did not ask for reduced motion */
@media (prefers-reduced-motion: no-preference) {
  html { scroll-behavior: smooth; }
}

/* Keep the target visible below a sticky header */
:target { scroll-margin-top: 5rem; }
```
```js Przewijanie z JS
const reduce = matchMedia("(prefers-reduced-motion: reduce)").matches;
const form = document.getElementById("booking-form");

form?.scrollIntoView({ behavior: reduce ? "instant" : "smooth", block: "start" });
// scrollIntoView does not move focus: move it so Tab continues from the form
form?.focus({ preventScroll: true });
```
X: `behavior: "smooth"` wpisane na sztywno w JS, które ignoruje preferencję użytkownika.
X: Przewinięcie do sekcji bez przeniesienia focusu; kolejne naciśnięcie Tab wraca do miejsca sprzed skoku.

@cl-group ARIA
sources: MDN: ARIA | https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA ; W3C: Using ARIA | https://www.w3.org/TR/using-aria/ ; W3C: WAI-ARIA 1.2 | https://www.w3.org/TR/wai-aria-1.2/

[aria-hidden-body] critical
T: Nie ustawiaj aria-hidden na body
D: `aria-hidden="true"` na `<body>` ukrywa całą stronę przed czytnikami ekranu, choć nadal da się ją obsługiwać klawiaturą. Zdarza się to przy źle zaimplementowanych modalach, które "ukrywają tło", lub w skryptach, które nie sprzątają po sobie.
W: Dla niewidomego użytkownika serwis przestaje istnieć: czytnik nie ma czego ogłosić, a Tab nadal przesuwa niewidoczny dla niego focus.
W: Modal renderowany przez portal wewnątrz `<body>` również znika, bo `aria-hidden` obejmuje wszystkich potomków i dziecko nie może się "odkryć" przez `aria-hidden="false"`.
W: axe przypisuje regułę do WCAG 1.3.1 i 4.1.2 (poziom A).
V: axe-core (reguła `aria-hidden-body`) lub ręcznie w panelu Elements przy otwartym i po zamknięciu modala.
```html Źle
<body aria-hidden="true">
  <main>...</main>
  <div role="dialog" aria-modal="true" aria-labelledby="t">...</div>
</body>
```
```html Dobrze
<body>
  <!-- dialog.showModal() makes everything outside the dialog inert automatically -->
  <div id="app">...</div>
  <dialog id="booking-dialog" aria-labelledby="booking-title">
    <h2 id="booking-title">Potwierdź rezerwację</h2>
  </dialog>
  <!-- Custom modal instead: set inert on #app only while it is open -->
</body>
```
X: Biblioteka modali ustawia `aria-hidden` na tle, ale nie usuwa go, gdy komponent zostanie odmontowany w trakcie animacji zamykania.

[aria-input-field-name] critical
T: Każde pole wejściowe ma dostępną nazwę
D: Elementy z rolą pola (`combobox`, `listbox`, `searchbox`, `slider`, `spinbutton`, `textbox`) muszą mieć nazwę, inaczej czytnik ogłosi tylko "pole edycji" bez kontekstu.
W: Czytnik ogłosi "pole edycji, puste" lub "suwak, 1500"; użytkownik nie wie, czy wpisuje miasto wylotu, czy datę powrotu.
W: `<label for>` działa tylko z natywnymi polami, więc `div` z `role="combobox"` nie dostanie z niego nazwy; potrzebne jest `aria-labelledby` lub `aria-label`.
W: Nazwa jest też celem komend głosowych ("kliknij Miasto wylotu" w Voice Control), więc jej brak wyklucza osoby sterujące komputerem głosem.
V: Panel Accessibility w DevTools (Computed name) lub axe (reguła `aria-input-field-name`).
```html Źle
<span>Miasto wylotu</span>
<div role="combobox" aria-expanded="false" contenteditable="true"></div>

<label for="guests">Liczba gości</label>
<div id="guests" role="spinbutton" tabindex="0" aria-valuenow="2"></div>
```
```html Dobrze
<span id="from-label">Miasto wylotu</span>
<div role="combobox" aria-labelledby="from-label" aria-expanded="false"
     aria-controls="from-list" contenteditable="true"></div>

<span id="guests-label">Liczba gości</span>
<div role="spinbutton" aria-labelledby="guests-label" tabindex="0"
     aria-valuenow="2" aria-valuemin="1" aria-valuemax="9"></div>
```
X: Budowanie własnej kontrolki tam, gdzie wystarczy natywny `<input>`, `<select>` lub `<input type="range">` z `<label>`.
S: W3C Understanding 4.1.2: Name, Role, Value | https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html

[aria-labels] high
T: Każdy element interaktywny ma dostępną nazwę
D: Przyciski z samą ikoną, linki-obrazki i własne kontrolki potrzebują nazwy z treści, `aria-label` lub `aria-labelledby`. Bez niej są dla czytnika "przycisk" bez znaczenia.
W: Na liście 20 ofert z ikonami serca i kosza czytnik ogłosi 40 razy "przycisk"; użytkownik nie wie, który dodaje do ulubionych, a który usuwa.
W: Nazwa musi zawierać widoczny tekst (WCAG 2.5.3 Label in Name): jeśli przycisk pokazuje "Szukaj", a `aria-label` brzmi "Wyślij formularz", komenda głosowa "kliknij Szukaj" nie zadziała.
W: Puste linki i przyciski należą do najczęstszych błędów w corocznym raporcie WebAIM Million, a naruszają WCAG 4.1.2 i 2.4.4 (poziom A).
V: Przejdź Tabem z włączonym czytnikiem ekranu lub sprawdź Computed name w panelu Accessibility w DevTools.
```html Źle
<button class="icon-btn"><svg>...</svg></button>
<a href="/oferty/kreta"><img src="kreta.avif"></a>
```
```html Dobrze
<button class="icon-btn" aria-label="Dodaj do ulubionych: Hotel Aquila, Kreta">
  <svg aria-hidden="true">...</svg>
</button>
<a href="/oferty/kreta">
  <img src="kreta.avif" alt="Kreta, 7 nocy od 2 499 zł">
</a>
```
X: `aria-label` na przycisku z widocznym tekstem: nadpisuje treść i łatwo rozjeżdża się z tym, co widać.
X: Ta sama nazwa ("Więcej") dla wielu linków; dodaj kontekst, np. "Więcej o Hotelu Aquila".

[aria-live-regions] high
T: Ogłaszaj dynamiczne zmiany przez regiony live
D: Komunikaty pojawiające się bez przeładowania (wyniki wyszukiwania, błędy, "dodano do koszyka") powinny trafić do `aria-live="polite"`, `role="status"` lub `role="alert"`. Region musi istnieć w DOM, zanim zmieni się jego treść.
W: Osoba niewidoma po kliknięciu "Dodaj do koszyka" nie widzi zmiany licznika; bez regionu live nie wie, czy akcja się udała, i klika ponownie.
W: Region wstawiony do DOM razem z treścią zwykle nie zostaje ogłoszony, bo technologie asystujące reagują na zmiany w już zarejestrowanym regionie.
W: `assertive` (i `role="alert"`) przerywa bieżący odczyt; nadużywany sprawia, że użytkownik gubi wątek, dlatego domyślnie używaj `polite` lub `status`, a `alert` tylko dla błędów.
W: Wymaga tego WCAG 4.1.3 Status Messages (AA).
V: Wywołaj akcję z włączonym NVDA lub VoiceOver i sprawdź, czy komunikat zostaje odczytany, i to tylko raz.
```tsx React
// The region is rendered once (empty) and only its text changes
export function SearchStatus({ count, loading }: { count: number; loading: boolean }) {
  return (
    <p role="status" aria-live="polite" className="sr-only">
      {loading ? "" : `Znaleziono ${count} ofert`}
    </p>
  );
}

// Bad: {!loading && <p role="status">Znaleziono {count} ofert</p>}
// The region appears together with its text and is often not announced.
```
X: `aria-live` dodane do `role="alert"`: VoiceOver na iOS może przeczytać komunikat dwukrotnie.
X: Linki i przyciski w treści regionu: czytnik ogłosi tylko tekst, bez informacji, że można w nie kliknąć.
S: W3C Understanding 4.1.3: Status Messages | https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html ; MDN: ARIA live regions | https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions

[aria-required-children] high
T: Role ARIA zawierają wymagane role-dzieci
D: Niektóre role wymagają konkretnych dzieci, np. `list` → `listitem`, `tablist` → `tab`, `listbox` → `option`, `menu` → `menuitem`. Bez nich czytnik nie zrozumie struktury widgetu.
W: Czytnik ogłasza strukturę na podstawie dzieci: "lista, 5 elementów", "karta 2 z 4". Bez właściwych ról tej informacji nie ma, a nawigacja strzałkami w widgecie przestaje działać.
W: Najczęstsza przyczyna to dzieci z inną rolą, np. zwykłe `<button>` w `role="tablist"` zamiast elementów z `role="tab"`.
W: axe przypisuje regułę do WCAG 1.3.1 Info and Relationships (A): relacje widoczne na ekranie muszą być dostępne programowo.
V: axe (reguła `aria-required-children`) lub drzewo dostępności w DevTools.
```html Źle
<div role="tablist" aria-label="Typ wyjazdu">
  <button>Wczasy</button>
  <button>City break</button>
</div>
```
```html Dobrze
<div role="tablist" aria-label="Typ wyjazdu">
  <button role="tab" id="t-beach" aria-selected="true" aria-controls="p-beach">Wczasy</button>
  <button role="tab" id="t-city" aria-selected="false" aria-controls="p-city" tabindex="-1">City break</button>
</div>
```
X: Nadanie roli kontenera (`menu`, `listbox`, `grid`) "dla porządku": rola zobowiązuje do pełnego wzorca, łącznie z obsługą klawiatury.

[aria-valid-attr] high
T: Używaj tylko istniejących atrybutów ARIA
D: Literówki typu `aria-lable` są ignorowane przez przeglądarkę, więc element zostaje bez nazwy lub stanu. Dozwolone są tylko atrybuty ze specyfikacji WAI-ARIA.
W: Literówka nie daje błędu w konsoli ani w TypeScript: JSX akceptuje dowolny atrybut z myślnikiem, więc `aria-lable` przechodzi kompilację i często code review.
W: Przycisk z `aria-lable="Zamknij"` jest dla czytnika bezimienny, choć autor jest przekonany, że go opisał.
W: Tak samo nic nie robią atrybuty wymyślone (`aria-name`, `aria-tooltip`, `aria-text`), których nie ma w specyfikacji.
V: axe (`aria-valid-attr`) w testach oraz eslint-plugin-jsx-a11y (reguła `aria-props`) już w edytorze.
```html Źle
<button aria-lable="Zamknij"><svg aria-hidden="true">...</svg></button>
<input id="pesel" aria-requierd="true" aria-describeby="pesel-hint">
```
```js eslint.config.js
import jsxA11y from "eslint-plugin-jsx-a11y";

export default [
  jsxA11y.flatConfigs.recommended,
  {
    rules: {
      "jsx-a11y/aria-props": "error", // unknown aria-* names, e.g. aria-lable
      "jsx-a11y/aria-proptypes": "error", // invalid values, e.g. aria-hidden="yes"
    },
  },
];
```
X: Poleganie wyłącznie na lincie JSX; atrybuty dodawane w szablonach CMS lub przez `setAttribute` wychwyci dopiero axe na wyrenderowanej stronie.

[duplicate-id-aria] high
T: Unikalne ID wskazywane przez atrybuty ARIA
D: `aria-labelledby`, `aria-describedby`, `aria-controls` i `<label for>` odwołują się do ID. Duplikat sprawia, że przeglądarka bierze pierwszy pasujący element, często niewłaściwy.
W: Gdy dwa pola mają podpowiedź z `id="hint"`, przy drugim polu czytnik odczyta podpowiedź pierwszego, np. format PESEL przy numerze telefonu.
W: Duplikaty powstają zwykle przy powtarzanych komponentach: karta oferty na liście, kilka formularzy na stronie, ten sam filtr w panelu bocznym i w szufladzie mobilnej.
W: axe przypisuje regułę do WCAG 4.1.2 (A); klik w etykietę z duplikatem ID też przenosi focus do złego pola.

```tsx Toaster.tsx

export function Toaster({ toasts, dismiss }: ToasterProps) {
  const urgent = toasts.filter((t) => t.type === "error");
  const polite = toasts.filter((t) => t.type !== "error");
  return (
    <div className="toaster">
      <div role="status" aria-live="polite">
        {polite.map((t) => <Toast key={t.id} toast={t} onDismiss={() => dismiss(t.id)} />)}
      </div>
      <div role="alert">
        {urgent.map((t) => <Toast key={t.id} toast={t} onDismiss={() => dismiss(t.id)} />)}
      </div>
    </div>
  );
}
```
```tsx Toast.tsx
const DURATION: Record<ToastType, number | null> = { success: 5000, info: 7000, warning: 10000, error: null };

export function Toast({ toast, onDismiss }: { toast: ToastData; onDismiss: () => void }) {
  const [paused, setPaused] = useState(false);
  useEffect(() => {
    const ms = DURATION[toast.type];
    if (ms === null || paused) return; // errors stay until dismissed
    const timer = setTimeout(onDismiss, ms);
    return () => clearTimeout(timer);
  }, [toast.type, paused, onDismiss]);

  return (
    <div className="toast" onMouseEnter={() => setPaused(true)} onMouseLeave={() => setPaused(false)}
         onFocus={() => setPaused(true)} onBlur={() => setPaused(false)}>
      <p>{toast.message}</p>
      <button type="button" onClick={onDismiss} aria-label="Zamknij powiadomienie">×</button>
    </div>
  );
}
```

```ts
const tabs = [...document.querySelectorAll<HTMLButtonElement>('[role="tab"]')];

function select(tab: HTMLButtonElement) {
  for (const t of tabs) {
    const active = t === tab;
    t.setAttribute("aria-selected", String(active));
    t.tabIndex = active ? 0 : -1; // roving tabindex
    document.getElementById(t.getAttribute("aria-controls")!)!.hidden = !active;
  }
  tab.focus();
}

tabs.forEach((tab, i) => {
  const last = tabs.length - 1;
  const keys: Record<string, number> = { ArrowRight: i === last ? 0 : i + 1, ArrowLeft: i === 0 ? last : i - 1, Home: 0, End: last };
  tab.addEventListener("click", () => select(tab));
  tab.addEventListener("keydown", (e) => {
    if (e.key in keys) { e.preventDefault(); select(tabs[keys[e.key]]); }
  });
});
```

D: Treść unika określeń stygmatyzujących i wykluczających; dotyczy też komunikatów błędów, nazw w interfejsie i opisów alternatywnych.
W: Określenia typu "kaleka" czy "przykuty do wózka" zrażają część odbiorców i szkodzą wizerunkowi marki szybciej niż jakikolwiek błąd techniczny.
W: Komunikat błędu, który obwinia użytkownika ("Wpisałeś błędne dane, spróbuj jeszcze raz"), zwiększa frustrację i porzucenia formularzy.
W: Formularze zakładające jedną płeć lub "imię ojca" wykluczają realnych klientów; neutralne sformułowania działają dla wszystkich.
V: Przegląd treści z redaktorem i listą zakazanych zwrotów w słowniku projektu; linter alex działa tylko dla angielskiego, więc dla polskiego potrzebny jest własny słownik lub przegląd ręczny.
```html Źle
<p>Pokoje dla inwalidów dostępne na parterze.</p>
<p class="error">Podałeś zły numer telefonu!</p>
<label for="title">Pan / Pani</label>
```
```html Dobrze
<p>Pokoje dostosowane dla osób z niepełnosprawnościami są na parterze.</p>
<p class="error">Numer telefonu powinien mieć 9 cyfr, np. 600 123 456.</p>
<label for="title">Forma zwracania się (opcjonalnie)</label>
```
X: Wymuszanie płci w formularzu tylko po to, by dobrać formę "Szanowny Pan/Pani".

[plain-language] medium
T: Prosty, zrozumiały język
D: Krótkie zdania, znane słowa, objaśnione skróty. Pomaga osobom z niepełnosprawnościami poznawczymi, obcokrajowcom i wszystkim czytającym w pośpiechu.
W: Większość ludzi skanuje stronę zamiast ją czytać; krótkie zdania z najważniejszą informacją na początku są zrozumiane od razu.
W: Żargon branżowy ("OWU", "TFG", "dopłata paliwowa wg taryfy") rodzi pytania do infolinii i porzucone rezerwacje.
W: Prosty język to część wytycznych WCAG 3.1 (np. 3.1.4 skróty, 3.1.5 poziom czytania, AAA) i wymóg dla wielu serwisów publicznych.
V: Oceń czytelność (np. indeks FOG dla polskiego, narzędzie Jasnopis) i poproś kogoś spoza projektu o przeczytanie kluczowych ekranów.

```html Źle
<p>Zgodnie z OWU rezygnacja z imprezy turystycznej po terminie wskazanym w § 7 ust. 3 skutkuje

```

```html Dobrze
<ul>
```

[heading-hierarchy] critical
T: Logiczna hierarchia nagłówków
D: Jeden `h1` z tematem strony, a pod nim `h2`, `h3` bez przeskakiwania poziomów. Użytkownicy czytników nawigują po nagłówkach jak po spisie treści.
W: Według ankiet WebAIM większość użytkowników czytników ekranu szuka informacji na nowej stronie właśnie skacząc po nagłówkach (klawisz H w NVDA i JAWS).
W: Nagłówki z `div class="title"` są dla czytnika zwykłym tekstem; strona wygląda na uporządkowaną, ale "spisu treści" nie ma.
W: Czytelna hierarchia pomaga też wyszukiwarkom i narzędziom AI zrozumieć, o czym są poszczególne sekcje strony.
V: Rozszerzenie typu HeadingsMap lub lista nagłówków w czytniku ekranu (NVDA: Insert+F7, zakładka Nagłówki); sprawdź, czy sam konspekt opisuje stronę.
```html Dobrze
<h1>Wakacje w Grecji 2027</h1>
  <h2>Najpopularniejsze kierunki</h2>
    <h3>Kreta</h3>
    <h3>Rodos</h3>
  <h2>Oferty last minute</h2>
    <h3>Korfu, 7 nocy od 2899 zł</h3>
  <h2>Praktyczne informacje</h2>
    <h3>Pogoda i najlepszy termin</h3>
    <h3>Dokumenty i waluta</h3>
```
X: Wybieranie poziomu nagłówka po wielkości czcionki zamiast po miejscu w strukturze.
X: Zakładanie, że `<section>` "resetuje" poziomy: algorytm outline z HTML5 nigdy nie zadziałał w przeglądarkach i został usunięty ze specyfikacji.
S: W3C Understanding 2.4.6: Headings and Labels | https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html

[content-without-css] high
T: Treść zrozumiała bez CSS
D: Kolejność w DOM odpowiada kolejności czytania, a kluczowe informacje nie są wstawiane wyłącznie przez CSS (`::before`, obrazy tła). Tak treść odczytają czytniki, tryb czytania i wyszukiwarki.
W: Czytnik ekranu czyta DOM po kolei; jeśli cena jest wizualnie przy tytule, a w kodzie na końcu karty, kontekst się gubi.
W: Treść z `content: "..."` i obrazów tła nie da się zaznaczyć, skopiować ani przetłumaczyć, a tryby czytania i własne style użytkownika ją pomijają.
W: Przy wolnym łączu lub błędzie CDN arkusz stylów może się nie wczytać; strona dalej powinna dać się użyć.
V: Wyłącz style (np. Web Developer extension: CSS, Disable All Styles lub Firefox: Widok, Styl strony, Bez stylu) i sprawdź, czy strona ma sens i właściwą kolejność.
```css Źle
/* Essential info lives only in CSS */
.offer--promo::before { content: "Promocja -20%"; }
.badge-allinclusive { background-image: url(/img/all-inclusive-label.png); }
```
```html Dobrze
<article class="offer">
  <h3>Kreta, Hersonissos</h3>
  <p class="offer__promo">Promocja -20%</p>
  <p>Wyżywienie: all inclusive</p>
  <p class="offer__price">2799 zł <s>3499 zł</s></p>
</article>
```
X: Zmiana kolejności kolumn przez `order` lub `grid-area` tak, że DOM opowiada inną historię niż ekran.
S: W3C Understanding 1.3.2: Meaningful Sequence | https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html

[duplicate-id-active] high
T: Unikalne ID elementów aktywnych
D: Fokusowalne elementy z powtórzonym ID psują powiązania z etykietami i skrypty. W komponentach generuj ID (`useId`), zamiast wpisywać je na sztywno.
W: `<label for>`, `aria-labelledby` i `aria-describedby` biorą pierwszy element o danym ID; drugie pole dostaje cudzą etykietę lub żadną.
W: Komponent z na sztywno wpisanym `id="email"` wyrenderowany dwa razy (np. formularz w stopce i w modalu) to najczęstsze źródło duplikatów.
W: WCAG 2.2 uznało kryterium 4.1.1 Parsing za przestarzałe, ale skutki duplikatów nadal łamią 1.3.1 i 4.1.2, a `getElementById` zwraca nie ten element.
V: axe (`duplicate-id-aria`), Nu Html Checker lub w konsoli: `[...document.querySelectorAll('[id]')].map(e => e.id).filter((id, i, a) => a.indexOf(id) !== i)`.
```tsx Dobrze
import { useId } from "react";

export function EmailField({ error }: { error?: string }) {
  const id = useId(); // unique per component instance, stable across SSR and hydration
  return (
    <>
      <label htmlFor={`${id}-email`}>E-mail</label>
      <input id={`${id}-email`} type="email" aria-describedby={error ? `${id}-err` : undefined} />
      {error && <p id={`${id}-err`}>{error}</p>}
    </>
  );
}
```
X: Generowanie ID przez `Math.random()`; ID różni się między serwerem a klientem i psuje hydrację.

[navigation-landmark] high
T: Nawigacja w landmarku nav
D: Główne menu, menu stopki i breadcrumbs są w `<nav>`; kilka nawigacji rozróżnia `aria-label` ("Główna", "Stopka", "Ścieżka").
W: Czytniki ekranu pozwalają skoczyć prosto do landmarku (NVDA: klawisz D, VoiceOver: rotor), zamiast przechodzić przez całą stronę.
W: Bez etykiet użytkownik słyszy trzy razy "nawigacja" i nie wie, która jest którą.
W: Landmarki (`header`, `nav`, `main`, `footer`) to też mechanizm pomijania bloków z WCAG 2.4.1.
V: Lista landmarków w czytniku ekranu lub rozszerzenie Landmarks; każdy `nav` powinien mieć unikalną nazwę, gdy jest ich więcej niż jeden.
```html Dobrze
<header>
  <nav aria-label="Główna">
    <ul><li><a href="/last-minute">Last minute</a></li><li><a href="/kierunki">Kierunki</a></li></ul>
  </nav>
</header>
<nav aria-label="Ścieżka">
  <ol><li><a href="/">Start</a></li><li><a href="/grecja">Grecja</a></li><li aria-current="page">Kreta</li></ol>
</nav>
<main id="main">...</main>
<footer>
  <nav aria-label="Stopka">...</nav>
</footer>
```
X: `aria-label="Nawigacja główna"`; czytnik powie "Nawigacja główna, nawigacja", bo rolę dodaje sam.
X: Owijanie w `<nav>` każdej grupy linków, np. tagów pod artykułem; landmarków ma być kilka, nie kilkanaście.

[accessible-tables] medium
T: Semantyczne tabele danych
D: Tabele danych mają `<caption>`, nagłówki `<th scope="col|row">` i nie są używane do układu strony.
W: Przy przechodzeniu po komórkach czytnik ogłasza nagłówki kolumny i wiersza ("Lipiec, Kreta, 3499 zł"); bez `th` słychać same liczby.
W: `<caption>` nazywa tabelę i pojawia się na liście tabel w czytniku, więc użytkownik wie, czy warto do niej wchodzić.
W: Tabela użyta do układu strony każe czytnikowi ogłaszać "tabela, 3 kolumny" przy zwykłym tekście i psuje responsywność.
V: Odczytaj tabelę czytnikiem ekranu (NVDA: Ctrl+Alt+strzałki); przy przechodzeniu po komórkach powinny być ogłaszane nagłówki.

```html Dobrze
<table>

  </thead>
  <tbody>
    <tr><th scope="row">Aldemar Knossos</th><td>4299 zł</td><td>4599 zł</td></tr>
    <tr><th scope="row">Stella Village</th><td>3499 zł</td><td>3799 zł</td></tr>
  </tbody>
</table>
```
X: `display: block` lub `grid` na `<table>` w RWD bez sprawdzenia; część przeglądarek gubiła wtedy semantykę tabeli.

[definition-list] medium
T: Poprawna struktura listy definicji
D: `<dl>` zawiera tylko grupy `<dt>` i `<dd>` (ewentualnie owinięte w `<div>`, plus `script`/`template`). Inne dzieci psują semantykę.
W: Czytnik ogłasza listę i liczbę elementów; obcy element w środku sprawia, że pary termin-opis są źle liczone lub w ogóle nie rozpoznane.
W: `<dl>` dobrze pasuje do par klucz-wartość w kartach ofert (termin, wyżywienie, wylot), więc warto go używać poprawnie.
V: axe (`definition-list`) lub Nu Html Checker.
```html Źle
<dl>
  <h4>Szczegóły</h4>
  <dt>Wylot</dt><dd>Katowice, 12.07.2027</dd>
  <span>Wyżywienie: all inclusive</span>
</dl>
```
```html Dobrze
<h4>Szczegóły</h4>
<dl class="offer-details">
  <div><dt>Wylot</dt><dd>Katowice, 12.07.2027</dd></div>
  <div><dt>Wyżywienie</dt><dd>All inclusive</dd></div>
  <div><dt>Długość pobytu</dt><dd>7 nocy</dd></div>
</dl>
```

[dlitem] medium
T: Elementy dt i dd tylko wewnątrz dl
D: `<dt>` i `<dd>` poza `<dl>` (lub poza `<div>` będącym bezpośrednim dzieckiem `<dl>`) nie tworzą par termin-opis dla technologii asystujących.
W: Osierocone `dt`/`dd` to niepoprawny HTML; czytnik traktuje je jak zwykły tekst bez relacji termin-opis.
W: Problem zwykle pojawia się przy rozbijaniu listy na komponenty, gdy rodzic `<dl>` zostaje w innym komponencie niż dzieci.
V: axe (`dlitem`); w React sprawdź, czy komponent renderujący `dt`/`dd` jest zawsze używany wewnątrz `<dl>`.
```tsx Dobrze
// The component returns a group; the parent always provides <dl>
function Detail({ term, value }: { term: string; value: string }) {
  return (
    <div>
      <dt>{term}</dt>
      <dd>{value}</dd>
    </div>
  );
}

<dl>
  <Detail term="Transfer" value="W cenie" />
  <Detail term="Bagaż" value="20 kg" />
</dl>
```

[empty-heading] medium
T: Nagłówki zawierają tekst
D: Pusty nagłówek (np. tylko ikona lub obraz bez `alt`) pojawia się w nawigacji czytnika jako "nagłówek poziom 2" bez treści.
W: Użytkownik skaczący po nagłówkach trafia na pustą pozycję i traci orientację w strukturze strony.
W: Puste nagłówki często zostają po CMS-ie lub warunkowym renderowaniu, gdy brakuje danych.
V: axe (`empty-heading`) lub HeadingsMap; szukaj pozycji bez tekstu.

[heading-order] medium
T: Kolejność poziomów nagłówków
D: Poziomy rosną o jeden (h2, potem h3), nie skaczą (z h2 do h5). Wygląd ustawiasz w CSS, poziom wynika ze struktury.
W: Przeskok poziomu sugeruje użytkownikowi czytnika, że coś pominął; czytniki pozwalają skakać po konkretnych poziomach (NVDA: klawisze 1-6), więc brakujący poziom psuje tę nawigację.
W: Oddzielenie wyglądu od poziomu pozwala zespołowi designu zmieniać rozmiary bez psucia struktury.
V: axe (`heading-order`), HeadingsMap.
```html Źle
<h2>Opinie gości</h2>
<h5 class="small-title">Anna, lipiec 2026</h5>
```
```html Dobrze
<h2>Opinie gości</h2>
<h3 class="text-sm font-semibold">Anna, lipiec 2026</h3>
```
X: Komponent karty z na sztywno wpisanym `h4`, używany raz pod `h2`, raz pod `h3`; lepiej przekazać poziom jako prop.

[list-structure] medium
T: Listy zawierają tylko elementy listy
D: Bezpośrednimi dziećmi `<ul>`/`<ol>` mogą być tylko `<li>` (oraz `script`/`template`). Inaczej czytnik źle liczy elementy.
W: Czytnik ogłasza "lista, 5 elementów"; `div` lub nagłówek wewnątrz `ul` sprawia, że liczba i nawigacja po elementach są błędne.
W: To niepoprawny HTML, który różne przeglądarki i czytniki naprawiają na różne sposoby, więc zachowanie jest nieprzewidywalne.

```html Źle
<ul class="amenities">
  <h4>Udogodnienia</h4>
  <div class="item">Basen</div>
  <li>Wi-Fi</li>
</ul>
```
```html Dobrze
<h4>Udogodnienia</h4>
<ul class="amenities">
  <li>Basen</li>
  <li>Wi-Fi</li>
</ul>
```

[listitem] medium
T: Elementy li tylko wewnątrz list
D: `<li>` poza `<ul>`, `<ol>` lub `<menu>` traci znaczenie elementu listy.
W: Bez rodzica-listy czytnik nie powie, ile jest elementów ani który jest aktualny ("3 z 8").
W: Zwykle wynika z rozbicia na komponenty, gdzie `li` renderuje się w `div` zamiast w `ul`.
V: axe (`listitem`).
```tsx Źle
<div className="results">
  {offers.map((o) => <li key={o.id}>{o.title}</li>)}
</div>
```

```tsx Dobrze
<ul className="results">
  {offers.map((o) => <li key={o.id}>{o.title}</li>)}
</ul>
```

[semantic-lists] medium
T: Powiązane elementy jako listy
D: Menu, listy ofert, kroki procesu oznaczaj jako `ul`/`ol`/`dl`. Czytnik ogłosi "lista, 8 elementów", co pomaga zorientować się w treści.
W: Informacja o liczbie elementów pozwala zdecydować, czy przeglądać wyniki, czy od razu zawęzić filtry.
W: Czytniki pozwalają przeskoczyć całą listę jednym klawiszem (NVDA: L), zamiast przechodzić 20 kart po kolei.
W: `ol` dla kroków procesu (np. rezerwacji) przekazuje kolejność, a nie tylko wygląd numerków.
V: Przegląd DOM: powtarzające się elementy w samych `<div>` to sygnał do poprawy.
```html Dobrze
<h2>Wyniki wyszukiwania: 24 oferty</h2>
<ul class="offer-list" role="list"> <!-- role="list" restores semantics in Safari when list-style is none -->
  <li><article><h3>Kreta, Hersonissos</h3><p>od 3499 zł</p></article></li>
  <li><article><h3>Rodos, Lindos</h3><p>od 3199 zł</p></article></li>
</ul>

<ol class="steps">
  <li aria-current="step">Wybór pokoju</li>
  <li>Dane podróżnych</li>
  <li>Płatność</li>
</ol>
```
X: Zapominanie, że Safari z VoiceOver może nie ogłaszać listy z `list-style: none`; jeśli liczba elementów jest ważna, dodaj `role="list"`.

[table-duplicate-name] medium
T: Unikalne nazwy tabel
D: Gdy na stronie jest kilka tabel, ich `<caption>` lub `aria-label` powinny się różnić; `caption` i przestarzały atrybut `summary` nie powinny być identyczne.
W: Lista tabel w czytniku z trzema pozycjami "Cennik" nie pozwala wybrać właściwej.
W: Identyczne `caption` i `summary` sprawiają, że czytnik powtarza ten sam tekst dwa razy, nic nie dodając.
V: axe (`table-duplicate-name`); przejrzyj wszystkie `caption` na stronie z wieloma tabelami.
```html Dobrze
<table>
  <caption>Cennik: hotel Stella Village, lipiec 2027</caption>
  <!-- ... -->
</table>
<table>
  <caption>Cennik: hotel Stella Village, sierpień 2027</caption>
  <!-- ... -->
</table>
```
X: Używanie `summary` w nowym kodzie; atrybut jest przestarzały w HTML, opis umieść w `caption` lub tekście obok i powiąż przez `aria-describedby`.

[table-headers] medium
T: Poprawne nagłówki tabel danych
D: Każda tabela danych ma komórki `<th>` określające kolumny lub wiersze, a złożone tabele używają `scope` lub `headers`.
W: Bez `th` czytnik przy każdej komórce mówi tylko wartość; użytkownik musi pamiętać, co oznacza czwarta kolumna.
W: Pogrubienie `<td><b>` wygląda jak nagłówek, ale nie tworzy żadnej relacji w drzewie dostępności.
V: Odczyt czytnikiem ekranu, axe; w DevTools (Accessibility) nagłówki mają rolę `columnheader` lub `rowheader`.
```html Źle
<tr><td><b>Pokój</b></td><td><b>Cena</b></td></tr>
<tr><td>Standard</td><td>3499 zł</td></tr>
```
```html Dobrze
<tr><th scope="col">Pokój</th><th scope="col">Cena za osobę</th></tr>
<tr><th scope="row">Standard</th><td>3499 zł</td></tr>
<tr><th scope="row">Z widokiem na morze</th><td>3899 zł</td></tr>
```

[td-headers-attr] medium
T: Atrybut headers wskazuje istniejące nagłówki
D: W złożonych tabelach `<td headers="...">` musi odwoływać się do ID komórek `<th>` w tej samej tabeli.
W: Błędne ID (literówka, ID z innej tabeli) sprawia, że czytnik nie ogłosi żadnego nagłówka albo ogłosi zły.
W: `headers` jest potrzebny tylko w tabelach z wielopoziomowymi nagłówkami; w prostych wystarczy `scope`, co zmniejsza ryzyko błędów.
V: axe (`td-headers-attr`).
```html Dobrze
<table>
  <caption>Dopłaty do pokoi, lipiec 2027</caption>
  <tr><td></td><th id="std" scope="col">Standard</th><th id="sea" scope="col">Widok na morze</th></tr>
  <tr><th id="crete" colspan="3" scope="colgroup">Kreta</th></tr>
  <tr><th id="kn" scope="row">Knossos Beach</th>
    <td headers="crete kn std">0 zł</td><td headers="crete kn sea">400 zł</td></tr>
</table>
```

```tsx Ostrzeżenie przed wygaśnięciem
  useEffect(() => {
    const warnIn = expiresAt - Date.now() - 2 * 60_000; // warn 2 minutes before expiry
```

W: Natywny `<dialog>` otwarty przez `showModal()` sam przenosi focus do środka, blokuje tło i obsługuje Escape; własne modale muszą to odtworzyć ręcznie.
V: Wykonaj akcje klawiaturą i obserwuj `document.activeElement` (Live expression w DevTools).
```tsx Next.js App Router: focus na h1 po zmianie trasy
"use client";
import { usePathname } from "next/navigation";
import { useEffect, useRef } from "react";

// Render once in the root layout
export function RouteFocus() {
  const pathname = usePathname();
  const isFirstLoad = useRef(true);
  useEffect(() => {
    if (isFirstLoad.current) { isFirstLoad.current = false; return; } // do not move focus on initial load
    const heading = document.querySelector<HTMLElement>("main h1");
    if (!heading) return;
    heading.tabIndex = -1; // focusable by script, not in Tab order
    heading.focus();
  }, [pathname]);
  return null;
}
```
X: Po usunięciu pozycji z koszyka nie przenosisz focusu na następną pozycję lub nagłówek koszyka.
X: Po zamknięciu własnego modala focus nie wraca do przycisku, który go otworzył.

[skip-link] medium
