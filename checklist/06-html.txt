[doctype] critical
T: Doctype HTML5
D: `<!doctype html>` jako pierwsza linia dokumentu. Bez niego przeglądarka włącza tryb quirks z historycznymi błędami renderowania.
W: W trybie quirks inaczej liczona jest m.in. wysokość procentowa, wysokość linii przy obrazach inline i dziedziczenie fontów w tabelach; layout wygląda dobrze w jednym miejscu i rozjeżdża się w innym.
W: Krótka forma `<!doctype html>` wystarcza; stare DTD, np. XHTML 1.0 Transitional, potrafi włączyć tryb "almost standards" z innym renderowaniem obrazów w komórkach tabel.
W: Frameworki (Next.js, Astro) dodają doctype same, ale ręcznie pisane szablony, strony z CMS-ów i szablony e-maili często go gubią.
V: Źródło strony; w konsoli `document.compatMode === 'CSS1Compat'` (tryb quirks to `BackCompat`); Chrome zgłasza też tryb quirks w panelu Issues.
```html
<!doctype html>
<html lang="pl">
  <head>
    <meta charset="utf-8">
    <title>Wakacje w Grecji 2027</title>
  </head>
  <body>...</body>
</html>
```
```js Konsola DevTools
document.compatMode; // "CSS1Compat" = standards mode, "BackCompat" = quirks mode
```
X: Komentarz licencyjny lub dołączony fragment szablonu wygenerowany przed doctype.

[charset] critical
T: Kodowanie UTF-8
D: `<meta charset="utf-8">` jako pierwszy element head (w pierwszych 1024 bajtach). Inaczej polskie znaki mogą wyświetlić się błędnie.
W: Bez deklaracji przeglądarka zgaduje kodowanie; "Zażółć gęślą jaźń" odczytane jako Windows-1250 zamienia się w "ZaĹĽĂłĹ‚Ä‡ gÄ™Ĺ›lÄ… jaĹşĹ„", a strona traci wiarygodność.
W: Deklaracja musi znaleźć się w pierwszych 1024 bajtach; jeśli wcześniej stoją długie skrypty lub tagi Open Graph, przeglądarka może zacząć parsowanie od nowa lub użyć złego kodowania.
W: BOM ma pierwszeństwo przed nagłówkiem HTTP `Content-Type`, a ten przed meta; wszystkie źródła muszą wskazywać UTF-8.
V: Źródło strony (meta na początku head) i nagłówek `Content-Type` w panelu Network.
```html
<head>
  <meta charset="utf-8"> <!-- first element in head -->
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Last minute: Turcja, Egipt, Grecja</title>
</head>
```
```http Odpowiedź serwera
HTTP/2 200
content-type: text/html; charset=utf-8
```
X: `<meta charset>` umieszczony po skryptach analitycznych i dziesiątkach tagów meta.
X: Serwer wysyłający `charset=iso-8859-2` dla plików zapisanych w UTF-8.

[viewport] critical
T: Meta viewport
D: `<meta name="viewport" content="width=device-width, initial-scale=1">`. Bez niego telefony renderują stronę w szerokości ok. 980 px i pomniejszają.
W: Bez meta viewport media queries dla telefonów nie zadziałają, a tekst jest mikroskopijny; użytkownik musi powiększać i przewijać w poziomie.
W: Google indeksuje i ocenia strony w wersji mobilnej (mobile-first indexing), więc problem z widokiem mobilnym to problem z widocznością w wyszukiwarce.
W: Nie dodawaj `maximum-scale=1` ani `user-scalable=no`: blokują powiększanie i łamią WCAG 1.4.4 (Safari na iOS od lat i tak je ignoruje).
V: Źródło strony, test na telefonie lub w trybie urządzenia w DevTools; axe (`meta-viewport`) wykrywa blokadę zoomu.
```html
<!-- Bad: blocks pinch zoom, fails WCAG 1.4.4 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no">

<!-- Good -->
<meta name="viewport" content="width=device-width, initial-scale=1">

<!-- Good: on-screen keyboard resizes the layout (Chromium, Firefox) -->
<meta name="viewport" content="width=device-width, initial-scale=1, interactive-widget=resizes-content">
```
X: Blokowanie zoomu, "żeby inputy nie powiększały strony na iOS"; lepiej ustawić `font-size` pól na co najmniej 16 px.
S: MDN: Viewport meta tag | https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Viewport_meta_element

[lang-attribute] high
T: Atrybut lang na elemencie html
D: `<html lang="pl">` (kod BCP 47) wybiera właściwy syntezator mowy w czytnikach, reguły dzielenia wyrazów i tłumaczenie automatyczne. Fragmenty w innym języku mają własny `lang`.
W: Czytnik ekranu wybiera głos na podstawie `lang`; polski tekst czytany angielskim syntezatorem jest niezrozumiały. WCAG 3.1.1 (A).
W: Przeglądarka używa `lang` do dzielenia wyrazów (`hyphens: auto`), cudzysłowów w `q`, doboru fontów i decyzji, czy zaproponować tłumaczenie.
W: Wtrącenia w innym języku oznacz osobno (`<span lang="en">`): WCAG 3.1.2 (AA).
V: Źródło strony, axe (`html-has-lang`, `html-lang-valid`, `valid-lang`).
```html
<!doctype html>
<html lang="pl">
<body>
  <p>Pakiet obejmuje transfer i <span lang="en">late check-out</span> do 14:00.</p>
  <blockquote lang="de">Ein wunderbarer Urlaub auf Kreta!</blockquote>
</body>
</html>
```
```tsx app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="pl">
      <body>{children}</body>
    </html>
  );
}
```
X: `lang="en"` pozostawione z szablonu startowego (np. create-next-app) na polskiej stronie.
X: Jeden `lang` dla wszystkich wersji językowych serwisu zamiast ustawiania go per locale.
S: W3C Understanding 3.1.1: Language of Page | https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html

[direction-attribute] medium
T: Kierunek tekstu dla języków RTL
D: `dir="rtl"` dla arabskiego, hebrajskiego, perskiego itp. (na `html` lub fragmencie), `dir="auto"` dla treści od użytkowników w nieznanym języku, np. opinii i imion.
W: Bez `dir` tekst RTL wyświetla się z przestawioną interpunkcją i liczbami w złych miejscach, więc zdanie staje się nieczytelne.
W: Atrybut `dir`, a nie samo CSS `direction`, przekazuje kierunek także czytnikom ekranu, tłumaczom i wyszukiwarkom.
W: Właściwości logiczne CSS (`padding-inline`, `margin-inline-start`, `inset-inline-end`) odwracają layout automatycznie, bez osobnego arkusza RTL.
V: Podgląd wersji językowych RTL; ustaw `dir="rtl"` na `html` w DevTools i sprawdź, czy layout odwraca się lustrzanie.
```html
<!-- Arabic version of the site -->
<html lang="ar" dir="rtl">

<!-- Polish page with user reviews in any language -->
<p dir="auto">فندق رائع وإطلالة جميلة على البحر</p>
<p><bdi>יעל כהן</bdi> oceniła hotel na 9/10</p>
```
```css
/* Logical properties flip automatically in RTL */
.offer-card__badge { position: absolute; inset-inline-end: 1rem; }
.offer-card__body { padding-inline: 1.5rem; }
.icon-arrow:dir(rtl) { transform: scaleX(-1); }
```
X: `margin-left` i `left` na sztywno w komponentach, które mają działać w obu kierunkach.

[w3c-compliant] high
T: Poprawny HTML
D: Walidacja wyłapuje niezamknięte tagi, błędne zagnieżdżenia i nieistniejące atrybuty, które przeglądarki "naprawiają" na różne sposoby.
W: Parser HTML poprawia błędy według własnego algorytmu: `div` wewnątrz `p` zamyka akapit, a zagnieżdżony `form` jest ignorowany, więc DOM różni się od tego, co napisano.
W: Błędna struktura psuje drzewo dostępności (np. `li` poza listą) i powoduje błędy hydracji w React, gdy serwer i przeglądarka zbudują inny DOM.
W: Walidator wyłapuje literówki w atrybutach (`scr`, `aria-lable`), których przeglądarka nie zgłosi.
V: W3C Markup Validation Service (Nu Html Checker) lub html-validate w CI na zbudowanych stronach.
```html Źle
<p>Cena zawiera: <div>przelot, transfer, ubezpieczenie</div></p> <!-- p auto-closes before div -->
<ul><div><li>All inclusive</li></div></ul>                          <!-- div is not allowed in ul -->
<img scr="/img/hotel.avif" alt="Hotel Aegean Blue">                 <!-- typo, image never loads -->
```
```bash CI
# Validate the generated HTML in CI
npx html-validate "dist/**/*.html"
```
```json .htmlvalidate.json
{
  "extends": ["html-validate:recommended"],
  "rules": {
    "no-inline-style": "off"
  }
}
```
X: Walidowanie tylko szablonów źródłowych zamiast HTML wygenerowanego po SSR.
S: W3C: Markup Validation Service | https://validator.w3.org/

[unique-id] high
T: Unikalne ID
D: Każde `id` występuje na stronie tylko raz. Duplikaty ID psują etykiety formularzy, relacje ARIA, kotwice i skrypty.
W: `label for`, `aria-labelledby` i `aria-describedby` wskazują pierwszy element o danym ID; drugie pole zostaje bez etykiety lub dostaje cudzy opis błędu.
W: Kotwice (`#szczegoly`) i `getElementById` trafiają w pierwszy element, więc skrypt działa na złej karcie oferty.
W: W React generuj ID przez `useId()`, bo zahardkodowane `id="email"` zdubluje się, gdy komponent pojawi się na stronie dwa razy.
W: WCAG 2.2 usunęło kryterium 4.1.1 Parsing, ale zduplikowane ID nadal łamią relacje ARIA, czyli kryteria 1.3.1 i 4.1.2.
V: Walidator HTML, axe (`duplicate-id-aria`); w konsoli skrypt wyszukujący duplikaty.
```tsx
import { useId } from 'react';

export function TravelerField({ label }: { label: string }) {
  const id = useId(); // unique per instance, stable across SSR and hydration
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input id={id} name="traveler" aria-describedby={`${id}-hint`} />
      <p id={`${id}-hint`}>Imię i nazwisko jak w paszporcie</p>
    </div>
  );
}
```
```js Konsola DevTools
const ids = [...document.querySelectorAll('[id]')].map((el) => el.id);
console.log(ids.filter((id, i) => ids.indexOf(id) !== i));
```
X: Ten sam komponent modala lub formularza wyrenderowany dwukrotnie (wersja mobilna i desktopowa ukryta CSS-em).

[clean-up-comments] medium
T: Bez komentarzy i kodu debugowego na produkcji
D: Komentarze HTML, zakomentowane bloki i elementy testowe zwiększają rozmiar i mogą ujawniać informacje o systemie.
W: Źródło strony widzi każdy: nazwy wewnętrznych systemów, adresy stagingu, nazwiska i notatki TODO o lukach to darmowy rekonesans dla atakującego.
W: Zakomentowane bloki zwiększają rozmiar HTML, który przy SSR jest generowany i przesyłany przy każdym żądaniu.
W: Ukryte panele debugowe i `console.log` z danymi rezerwacji nie powinny trafić na produkcję; atrybuty `data-testid` są akceptowalne.
V: Źródło strony produkcyjnej (wyszukaj `<!--`); skan wyniku builda w CI.
```html Źle
<!-- TODO: remove before launch, old CMS at /cms-old (login: test) -->
<!-- <div class="promo-banner">Black Friday -30%</div> -->
<button class="debug-reset" style="display:none" onclick="resetCart()">Reset</button>
```
```bash CI
# Fail the build if TODO/DEBUG comments or debug markers leak into production HTML
if grep -rEn "<!-- ?(TODO|FIXME|DEBUG)|debug-reset" dist --include="*.html"; then
  echo "Debug artifacts found in build output"
  exit 1
fi
```
X: Usuwanie wszystkich komentarzy z wyniku SSR: znaczniki Reacta, np. `<!--$-->`, są częścią mechanizmu hydracji.

[noscript-tag] medium
T: Treść zastępcza w noscript
D: Gdy JS jest wyłączony lub zablokowany, `<noscript>` informuje użytkownika, co zrobić. Kluczowa treść powinna być jednak w HTML z serwera (SSR).
W: Pusta strona bez komunikatu wygląda na awarię serwisu; `noscript` przynajmniej podpowiada alternatywę, np. telefon do biura.
W: Google renderuje JavaScript, ale treść obecna w HTML z serwera jest indeksowana szybciej i pewniej; `noscript` nie zastąpi SSR.
W: `noscript` nie pomoże, gdy JS jest włączony, ale się nie wykonał (błąd w bundlu, zablokowany CDN, zerwane połączenie); na to potrzebny jest SSR i obsługa błędów.
V: Wyłącz JavaScript w DevTools (Command Menu: Disable JavaScript) i odśwież stronę.
```html
<body>
  <noscript>
    <p class="notice">
      Wyszukiwarka ofert wymaga JavaScriptu. Możesz też zarezerwować wyjazd telefonicznie:
      <a href="tel:+48221234567">22 123 45 67</a>.
    </p>
  </noscript>
  <!-- Key content is server-rendered, so it is readable without JS -->
  <main id="main">...</main>
</body>
```
X: Cała aplikacja renderowana tylko po stronie klienta, a w `noscript` jedynie "Włącz JavaScript".

[defer-async] high
T: Skrypty z defer, async lub type=module
D: Zwykły `<script>` w head blokuje parsowanie HTML. `defer` lub `type="module"` (kolejność zachowana) dla skryptów aplikacji, `async` dla niezależnych, np. analityki.
W: Parser zatrzymuje się na każdym klasycznym skrypcie, pobiera go i wykonuje; na wolnym łączu mobilnym to sekundy białego ekranu i gorsze FCP oraz LCP.
W: `defer` wykonuje skrypty w kolejności po sparsowaniu dokumentu, przed `DOMContentLoaded`; `async` uruchamia skrypt zaraz po pobraniu, w dowolnej kolejności, więc nie nadaje się do skryptów zależnych.
W: Skrypty `type="module"` są odroczone domyślnie; dodanie do nich `async` uruchamia je od razu po pobraniu.
V: Head strony, Lighthouse (zasoby blokujące renderowanie), panel Performance w DevTools.
```html
<head>
  <!-- Bad: blocks HTML parsing -->
  <script src="/js/vendor.js"></script>

  <!-- Good: app code, runs in order after parsing -->
  <script defer src="/js/vendor.js"></script>
  <script defer src="/js/app.js"></script>

  <!-- Good: ES module, deferred by default -->
  <script type="module" src="/js/booking.js"></script>

  <!-- Good: independent third-party script -->
  <script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX"></script>
</head>
```
X: `async` dla skryptu, który zależy od innego (np. wtyczka ładowana przed biblioteką).
X: `defer` na skrypcie inline: atrybut działa tylko ze `src`.

[subresource-integrity] high
T: Subresource Integrity dla skryptów z CDN
D: Atrybut `integrity="sha384-..."` (z `crossorigin`) sprawia, że przeglądarka odrzuci plik zmodyfikowany na serwerze CDN.
W: Przejęcie CDN lub konta wydawcy uderza we wszystkie strony, które ładują plik; z SRI przeglądarka zablokuje podmieniony skrypt zamiast go wykonać.
W: SRI działa tylko dla statycznych, wersjonowanych plików; skryptów generowanych dynamicznie (jak przejęty w 2024 r. polyfill.io) nie da się nim zabezpieczyć, więc lepiej hostować je samodzielnie.
W: Dla zasobów z innej domeny potrzebny jest `crossorigin="anonymous"` i nagłówki CORS po stronie CDN, inaczej przeglądarka zablokuje plik.
W: PCI DSS 4.0 (wymaganie 6.4.3) nakazuje kontrolę integralności skryptów na stronach płatności; SRI i CSP to podstawowe narzędzia.
V: Sprawdź skrypty i style ładowane z zewnętrznych domen; błąd integralności widać w konsoli, a zablokowany plik w Network.
```html
<script src="https://cdn.jsdelivr.net/npm/dayjs@1.11.13/dayjs.min.js"
        integrity="sha384-REPLACE_WITH_BASE64_HASH"
        crossorigin="anonymous"></script>
```
```bash
# Generate the SRI hash for a pinned file version
curl -s https://cdn.jsdelivr.net/npm/dayjs@1.11.13/dayjs.min.js \
  | openssl dgst -sha384 -binary | openssl base64 -A
```
X: SRI na adresie bez wersji (`@latest`): każda aktualizacja zmienia hash i blokuje skrypt.
S: MDN: Subresource Integrity | https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity

[html5-semantic-elements] high
T: Semantyczne elementy HTML5
D: `header`, `nav`, `main`, `article`, `section`, `aside`, `footer`, `button`, `figure`, `time` zamiast samych `div` i `span`. Dają dostępność, SEO i czytelny kod.
W: Czytnik ekranu ogłasza role ("nawigacja", "przycisk", "artykuł"); `div` z `onclick` jest dla niego zwykłym tekstem, niedostępnym z klawiatury.
W: Natywne elementy dają zachowanie za darmo: `button` reaguje na Enter i Spację, `details` się rozwija, `dialog` zarządza focusem.
W: Wyszukiwarki i tryby czytania (np. Safari Reader) łatwiej znajdują treść główną w `main` i `article`, a `time datetime` podaje datę w formacie maszynowym.
V: Przegląd DOM głównych szablonów; drzewo dostępności w DevTools (Elements, Accessibility).
```html Źle
<div class="header"><div class="menu">...</div></div>
<div class="offer">
  <div class="title">Hotel Aegean Blue</div>
  <span>12.05.2027</span>
  <div class="btn" onclick="book()">Rezerwuj</div>
</div>
```
```html Dobrze
<header><nav aria-label="Główna">...</nav></header>
<main>
  <article class="offer">
    <h2>Hotel Aegean Blue</h2>
    <p>Wylot: <time datetime="2027-05-12">12 maja 2027</time></p>
    <button type="button" onclick="book()">Rezerwuj</button>
  </article>
</main>
```
X: `section` jako zamiennik `div` bez nagłówka.
X: `button` do zmiany strony i `a` bez `href` do akcji: link prowadzi, przycisk działa.

[custom-element-accessibility] medium
T: Dostępne Web Components
D: Własne elementy nie mają wbudowanej semantyki: muszą ustawić rolę i stany (np. przez `ElementInternals`), obsługę klawiatury i focusu oraz udostępnić etykietę.
W: `<fav-toggle>` jest dla czytnika anonimowym kontenerem; bez roli i nazwy nie wiadomo, czy to przycisk, przełącznik, czy tekst.
W: `ElementInternals` ustawia domyślną rolę i stany ARIA bez dopisywania atrybutów, które autor strony może nadpisać; obsługują to wszystkie główne przeglądarki.
W: Shadow DOM przerywa relacje ID: `aria-labelledby` spoza komponentu nie widzi elementów w shadow root, więc etykietę trzeba przekazać atrybutem lub slotem.
W: `static formAssociated = true` z `ElementInternals` sprawia, że własne pole działa z `label`, walidacją i wysyłką formularza.
V: Panel Accessibility w DevTools (rola, nazwa, stany) i test klawiaturą oraz czytnikiem ekranu.
```ts fav-toggle.ts
// Accessible toggle button as an autonomous custom element
class FavToggle extends HTMLElement {
  #internals = this.attachInternals();

  connectedCallback() {
    this.#internals.role = 'button';
    this.#internals.ariaPressed = 'false';
    if (!this.hasAttribute('tabindex')) this.tabIndex = 0;
    this.addEventListener('click', () => this.toggle());
    this.addEventListener('keydown', (e) => {
      if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); this.toggle(); }
    });
  }

  toggle() {
    const pressed = this.#internals.ariaPressed === 'true';
    this.#internals.ariaPressed = String(!pressed);
  }
}
customElements.define('fav-toggle', FavToggle);
// Usage: <fav-toggle aria-label="Dodaj hotel do ulubionych">♥</fav-toggle>
```
X: Odtwarzanie zachowania przycisku od zera, gdy wystarczy natywny `<button>` wewnątrz shadow DOM.
X: Customized built-ins (`<button is="...">`): Safari ich nie obsługuje.

[breadcrumb-navigation] medium
T: Dostępne breadcrumbs
D: `<nav aria-label="Ścieżka">` z listą `<ol>`, ostatni element z `aria-current="page"`. Plus BreadcrumbList w danych strukturalnych.
W: Breadcrumbs pokazują, gdzie użytkownik jest w hierarchii (Grecja, Kreta, hotel), i pozwalają jednym kliknięciem wrócić do listy ofert.
W: `nav` z etykietą tworzy landmark, `ol` ogłasza liczbę poziomów, a `aria-current="page"` informuje, że to bieżąca strona.
W: BreadcrumbList pomaga Google zrozumieć strukturę serwisu i może zastąpić surowy adres URL ścieżką w wynikach wyszukiwania.
V: Odczyt czytnikiem ekranu, Rich Results Test.
```html
<nav aria-label="Ścieżka">
  <ol class="breadcrumbs">
    <li><a href="/">Strona główna</a></li>
    <li><a href="/wakacje/grecja">Grecja</a></li>
    <li><a href="/wakacje/grecja/kreta">Kreta</a></li>
    <li><a href="/hotel/aegean-blue" aria-current="page">Hotel Aegean Blue</a></li>
  </ol>
</nav>
```
```json JSON-LD
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Grecja", "item": "https://example.pl/wakacje/grecja" },
    { "@type": "ListItem", "position": 2, "name": "Kreta", "item": "https://example.pl/wakacje/grecja/kreta" },
    { "@type": "ListItem", "position": 3, "name": "Hotel Aegean Blue" }
  ]
}
```

[form-validation] high
T: Dostępna walidacja formularzy
D: Komunikaty błędów przy polach, powiązane przez `aria-describedby`, z `aria-invalid="true"`, opisujące, jak naprawić błąd. Nie tylko kolor. Podsumowanie błędów przy długich formularzach.

```html
  </div>
  <label for="email">E-mail</label>
```

```js
const form = document.querySelector('#booking');
const summary = document.querySelector('#error-summary');

form.addEventListener('submit', (e) => {
  const invalid = [...form.elements].filter((el) => el.willValidate && !el.checkValidity());
  if (!invalid.length) return;
  e.preventDefault();
  summary.querySelector('ul').replaceChildren(...invalid.map((el) => {
    el.setAttribute('aria-invalid', 'true');
    document.getElementById(`${el.id}-error`).textContent = el.dataset.error;
    const li = document.createElement('li');
    li.innerHTML = `<a href="#${el.id}"></a>`;
    li.firstChild.textContent = el.dataset.error;
    return li;
  }));
  summary.hidden = false;
  summary.focus(); // screen reader reads the summary heading and the list
});
```
